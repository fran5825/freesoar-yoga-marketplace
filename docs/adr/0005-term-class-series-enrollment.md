# ADR 0005: 期班整期報名以「整期報名紀錄」串起逐場報名

## Status

Accepted（2026-10-04，產品主人於 `/grill-with-docs` Q28 核准方向；實作前仍需逐票 Human Gate）

## Context

公司開課常以「一期兩到三個月」為單位，學員希望報名一次就涵蓋整期。原本的課程系列只是排程範本，每一場都是獨立的 `ClassSession` 與 `Enrollment`；名詞表也曾明定系列不是套裝課程。

產品主人確認需要「期班」與「整期報名」，並要求同時支援：中途加入（只報剩下的場次）、單場請假、退出整期、老師整期確認一次、補課場次自動報上，以及部分期班同時收單堂報名。

## Decision

- 每一場課仍是獨立的 `ClassSession`，每位學員在每一場仍有自己的 `Enrollment`；出席、名額、取消與完成都繼續以單場為單位。
- 新增一筆「整期報名紀錄」（暫名 `SeriesEnrollment`），代表「某位學員報名了某個期班」；屬於整期的每一場 `Enrollment` 指回這筆紀錄，並記錄來源：由整期報名新增，或報整期前已存在、被併入的單堂報名。整期被婉拒時，前者取消、後者脫離整期恢復為單堂。
- 整期確認、整期婉拒、退出整期、補課自動報上，都透過這筆紀錄找到底下的逐場報名，一次處理。
- 系列本身新增系列型態（持續開課／期班）與期班報名方式（只收整期／整期和單堂都收）。

## Alternatives considered

1. **只建逐場報名、不建整期紀錄**：一次報名時批次建立多筆 `Enrollment`。做不到「整期確認一次」、「退出整期」與「補課自動報上整期學員」，因為系統無法分辨哪些報名屬於同一次整期報名，也無法分辨整期學員與恰好每場都單堂報名的學員。
2. **只建整期紀錄、不建逐場報名**：報名掛在系列上。名額、請假、出席、單堂與整期混收、既有取消連帶規則都要重寫，且與既有以場次為中心的報名、通知、評價流程全面衝突。
3. **期班作為獨立的新課程實體**：與現有系列重複，老師要學第三種排程，也要重做系列頁與生成邏輯。

## Consequences

- 既有以場次為中心的報名、名額、取消與通知邏輯可以沿用；整期功能是加在上面的一層。
- 整期報名要同時鎖定多場課程檢查名額，必須固定鎖定順序以避免 deadlock，並與單場報名搶同一把鎖。
- 逐場報名與整期紀錄之間的狀態要保持一致（例如退出整期後，底下尚未開始的場次都要取消），需要在 `state-machines.md` 定義並以測試保護。
- 之後若要支援整期付款，付款可以掛在整期報名紀錄上，不必改逐場報名。
- 團主一次安排多堂課（backlog 第 18 項）之後可以沿用同一套模型。
