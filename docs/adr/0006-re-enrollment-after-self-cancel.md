# ADR 0006: 學員自己取消的報名，開課前可以重新報名

## Status

Accepted（2026-10-10，產品主人於 `/grill-with-docs` 核准；實作前仍需逐票 Human Gate）。取代 `enrollment` plan 的 D8「取消後不可重新報名」。

## Context

`enrollment` plan D8 選擇「取消後不可對同一堂重新報名」，理由是避免「取消又重新排隊」搶名額，並簡化資料庫唯一約束（`@@unique([classSessionId, userId])` 不分狀態）。實際使用上，學員開課前反悔、整期學員請假後想取消請假，都被擋下，產品主人認為不夠彈性。期班學員尤其常遇到很難找人代課或單買單堂。平台沒有候補排隊，取消會釋出名額、別人先報滿就報不了，原本的搶名額顧慮比當時預期的小。

## Decision

- 開課前自己取消（含整期請假）的報名可以重新報名，次數不限；課程開始後不能取消也不能重新報名。
- 只有「學員自己取消」的可以。老師婉拒、管理員取消、整期退出或婉拒連帶取消、整堂課取消都不行。要分辨來源，`Enrollment` 新增可為空的 `cancelledBy`（`member`／`teacher`／`admin`／`system`）；舊資料為 `NULL`，一律不能重新報名。
- 沿用同一筆報名紀錄，把 `cancelled` 改回有效狀態，不新增紀錄、不改唯一約束。重新報名與取消請假只保留最後狀態，不保留取消與重報的歷史。
- 需老師確認的單堂重新報名視為新申請。整期請假後反悔回到整期報名，狀態跟整期報名一致。
- 請假名額依期班模式處理：`term_only` 保留給請假的人（算占用），`term_and_single` 釋出給單堂報名，被買滿就不能取消請假。

## Alternatives considered

1. **維持 D8、只改文案**：最單純，但不解決學員的彈性需求。
2. **改唯一約束為「只擋有效狀態」，重報時新增一筆紀錄**：同一人同一堂會有多筆紀錄，名單、統計與整期連結都要改；而且仍然需要「誰取消的」才能擋老師婉拒。
3. **所有取消都能重新報名**：老師婉拒的人可以立刻重送，婉拒失去意義；管理員取消通常有原因。
4. **限制重新報名次數**：要多存計數，換來的好處很小，沒有候補排隊的情況下搶名額風險有限。

## Consequences

- 一個 additive migration（新 enum 與欄位、DB check）。所有寫入 `cancelled` 的地方都必須填 `cancelledBy`，漏填的新取消會變成「原因未記錄」而不能重新報名，要以測試涵蓋每個來源。
- 「占用名額」不再只是 `pending + confirmed`：`term_only` 期班要把請假中的報名算進去，必須集中成共用函式，否則各處名額判斷會不一致。
- `docs/domain/` 裡的 D8 說明與狀態機需同步更新。
- 重新報名會覆蓋 `notes` 與 `consentedAt`；V1 沒有需要「取消與重報歷史」的功能。若之後要做稽核或統計，需另外加歷史表。
