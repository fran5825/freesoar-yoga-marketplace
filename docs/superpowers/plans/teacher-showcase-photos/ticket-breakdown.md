## 各票範圍與完成標準

### 01 付款狀態 v0

- 範圍：以 [`2026-08-03-lightweight-payment-v0-plan.md`](../2026-08-03-lightweight-payment-v0-plan.md) 為基礎，不重寫。老師手動標記已收款，不經手金錢、不做金流。
- 開工前必須先處理：該計畫寫於 2026-08-03，**P5 的價格來源是 `DemandResponse.proposedPrice`，但老師開課沒有需求、也沒有價格欄位**（`ClassSession` 沒有 price）。價格已決定放 `ClassSession.priceNote`（文字），並更新該計畫與 `docs/domain/data-model.md`。該計畫狀態為 Draft，需 peer review 與產品主人決策，尚未授權施工。
- **第一步（規劃，不寫程式）**：把付款計畫第 0、0.1 節併回正文 §4–§9（schema、allowlist、Slice、測試矩陣）並重新 peer review，通過後才交 Builder。
- 2026-10-10 加入範圍（付款計畫第 0 節）：`priceNote`、老師的繳費規則與聯絡方式、報名快照、學員填轉帳後五碼。課程頁在報名前顯示價格與繳費規則（有填才顯示）。
- 完成標準：老師看得到每位學員「報名狀態」與「付款狀態」兩個分開的標籤，可標記已收款與已退款；學員看得到自己的付款狀態與老師收款資訊；管理員可標記；團主唯讀。

### 02 圖片基礎

- 範圍：`TeacherPhoto` 資料表、R2 儲存介面（上傳、取得顯示網址、刪除）、格式與大小檢查、自動縮圖、隨機 key、上傳提醒文字。不做任何畫面（畫面在 03）。
- 產品主人要做：開通 Cloudflare R2、建立 bucket 與 API token，自己填進 `.env`（不貼在對話）。
- 完成標準：測試環境能上傳一張照片並取得顯示網址；超過 5 MB 或格式不符會被拒絕；沒有設定金鑰時，其他功能不受影響（照片區顯示不可用）。

### 03 老師照片管理

- 範圍：老師資料頁新增「頭像與照片」區（最多 5 張、可排序、可刪除、可指定頭像）；沒照片時顯示簡單的上傳引導；老師申請表（`/teachers/join`）移除照片欄位（既有 `profilePhotoUrl` 舊資料保留、不再顯示或寫入）；只有審核通過的老師可上傳。
- 完成標準：老師能完成上傳→排序→指定頭像→刪除；刪除被使用中的照片前有提示；申請表不再有照片欄位；申請中的老師看不到上傳區；既有使用 `profilePhotoUrl` 的頁面（`src/domain/teacher-profile`、`organizer-class-proposal`、`demand-response/organizer-read-service` 等）改讀新頭像。

### 04 課程封面

- 範圍：建課頁與編輯頁新增「課程封面」（挑已上傳的照片或另外上傳）；系列封面由系列內各堂繼承；課程詳情頁頂端顯示封面。
- 單堂（不屬於系列）設自己的封面；系列設系列封面，系列場次不可設封面（寫入端拒絕，資料庫 check 約束，spec 6.3、M2）。
- 完成標準：單堂與系列都能設定與更換封面；系列場次寫入封面會被拒絕；刪除封面照片後課程不壞；沒封面時照常顯示。

### 05 課程卡片與課程頁改版

- 範圍：封面與老師頭像必須在 spec 7.1 列出的**所有**路由與 read service（含訪客與已登入會員兩套單堂查詢、系列頁、期班頁、老師端）一致顯示；依 spec 第 5 節改課程列表卡片（含 `/classes`、老師與團主端的課程列表是否一併套用，先在版面預覽中確認）；課程頁顯示老師頭像與名字。
- 先做版面預覽（有封面、沒封面、長課名、手機寬度）給產品主人確認，再套用到所有列表。
- 完成標準：spec 7.1 每一條路徑逐一有測試（有封面、沒封面各一）；有無封面卡片高度一致；手機寬度不爆版；通過 `docs/visual-acceptance-checklist.md`；不增加卡片資訊行數。

### 06 老師公開頁與課程頁連到老師

- 範圍：`/teachers/[teacherProfileId]`、老師資料頁的「公開我的頁面」開關（預設關）、課程頁頭像連到老師公開頁（公開頁關閉時不出現連結）、未公開或未審核通過回 404。
- 完成標準：spec 第 9 節對應項目全部通過；老師公開頁不顯示被管理員下架或老師刪除的照片（票 07 下架機制完成後補測）；做 security review（公開頁不外洩 email、電話、收款資訊）。老師頁的課程區只列公開列出的課程（沿用 `/classes` 的可見性規則，含單堂、系列、期班），並有公開與僅連結兩種驗收情境。

### 07 管理員下架與通知

- 範圍：管理員後台可下架照片並填原因；下架立即從所有頁面隱藏；老師收到站內通知；新增通知類型（spec M4），在 `EMAIL_POLICY` 對該類型使用空收件清單，落實「只發站內通知」。
- 完成標準：下架後課程封面回到色塊（spec 7.1 各路徑）、老師收到通知；老師公開頁不顯示被下架照片的檢查放在票 06（公開頁完成後補測）。

### 08 可複製文案模板

- 範圍：不呼叫 AI。老師開好課之後，用課程資料套固定模板，產生可複製貼到 Line 或 IG 的文字（招生公告、課前一天提醒、課後感謝）。
- 完成標準：三種模板文字語氣符合 `docs/context/voice-and-tone.md`；沒填的欄位整行不出現。

### 09 驗收與文件同步

- 範圍：總驗收。各文件已隨各票同步更新（見「共同規則」）；本票只檢查是否漏改、更新 spec 狀態，並做完整 E2E smoke、spec 7.1 全路徑旅程與 RWD 檢查。
- 完成標準：Quality Gates 全過；產品主人可獨立完成「老師上傳照片、建課設封面、公開老師頁、學員從分享連結看到圖文課程」整段旅程。

### 10 找第一位老師示範（產品主人）

- 目前沒有任何老師接觸紀錄。圖文做完後，用自己的一堂真實課程示範，並用策略文件的方式記錄卡點：開課、分享、報名、名單、付款。
- 成功標準沿用策略文件：2 位老師各開 2 堂課、10 位學員參與，每週總投入不超過 2 小時。

## 共同規則

- **文件隨票同步**（`AGENTS.md`：架構、權限、狀態機變動須在同一變更更新文件）：票 01 更新 `data-model.md`；票 02 更新 `data-model.md`（`TeacherPhoto`）；票 03 更新 `permissions.md`、`permissions-matrix.md`（老師管理自己的照片）；票 04 更新 `data-model.md`（`coverPhotoId` 與 check）；票 06 更新 `permissions*.md`、`route-map.md`（公開頁）；票 07 更新 `notification-spec.md`、`permissions*.md`（管理員下架）。文件修改前仍需產品主人核准 spec 第 7 節。

- 每次文件變更後依 `AGENTS.md` 做 self review；不 commit、不 push，除非產品主人明確要求。
- 動 schema 的票用 worktree 與獨立測試資料庫；測試用獨立埠（例如 3200）：`PORT=3200 npx playwright test ...`。
- 範圍外（不做）：教室獨立資料（backlog 第 21 項）、候補名單、AI 文案、金流自動化、照片編輯器。
