# 05：系列改課（只改這場／改這場和之後所有場次）

**What to build:** 老師改系列中的某一場時，可選「只改這場」或「改這場和之後所有場次」；後者同步更新系列設定，之後生成或追加的場次沿用。不能改星期幾。

**Workflow mode:** HEAVY

**Human Gate:** yes

**Risk flags:** STATE_MACHINE、PERMISSION、NOTIFICATION、CONCURRENCY（批次鎖多場）

規格：[4.5 改課](../../../../specs/teacher-class-scheduling-spec.md)（Q5、Q10）；情境 S14、S15；推導規則 4。

- [x] 套用範圍二選一，確認前顯示會影響的場次。

- [x] 通知規則同 04；依產品主人決定 A 改為每位學員只收一則（寫明影響他報名的幾堂）。

## 開工前設計（2026-10-05，待產品主人確認）

產品主人已同意推導規則 4（批次中任一場撞課或名額不足，整批不改）。文件已先更新：`state-machines.md`、`permissions.md`、`permissions-matrix.md`、`data-model.md`（RecurringClassSeries），標為「已核准・未實作」。

### 套用範圍與欄位

| 欄位 | 只改這場 | 改這場和之後所有場次 |
| --- | --- | --- |
| 標題、說明、課程風格、瑜伽類型 | 只改這場 | 每一場都改，系列設定也改 |
| 日期 | 可以改（例如把放假那週移到別天，見待確認 D） | **不能改**：每一場維持原本日期 |
| 上課時段（幾點到幾點） | 可以改 | 每一場套用新時段，系列設定也改 |
| 地點 | 可以改 | 每一場都改，系列設定也改 |
| 人數上限 | 可以改，不低於這場已報名人數 | 每一場都改，任一場已報名人數超過新上限就整批不改；系列設定也改 |
| 公開設定、是否需要確認報名 | 不能改（票 06／推導規則 6） | 同左 |
| 適合對象、準備事項（學員流程票 03／04 新增後） | 只改這場 | 同內容類欄位 |

「之後所有場次」＝這一場與之後所有尚未開始、未取消的場次（已開始、已完成、已取消的不動）。

### 鎖定與一致性

- **只改這場**：沿用票 04 的改課核心（鎖這一場 → 鎖老師），只是允許屬於系列的場次。系列設定不變。
- **改這場和之後所有場次**：一個 transaction 內 → `FOR UPDATE` 鎖本人系列列 → 鎖內重新讀取「這一場起」的場次集合 → 依 id 排序逐場 `FOR UPDATE` → 鎖老師並確認 `approved` → 驗證欄位 → 逐場檢查撞課（排除該場自己）與名額下限，**任一場不通過就整批不寫**並回報是哪一天 → 全部通過才逐場更新、再更新系列設定 → commit 後才發通知。
- 與其他操作不會互相卡住：生成更多、全部開放報名、從這場以後全部取消也是「系列 → 場次 → 老師」；單場報名與只改這場是「場次 → 老師」。都是同一方向。
- 系列頁與系列詳情 DTO 每一場改帶自己的 `capacity`，分母不再用系列的 `capacity`。

### 通知

- 只有改了時間或地點才通知，對象是受影響場次中 `pending`／`confirmed` 的學員；報名照樣保留。
- **待確認 A**：建議「每位學員只收一則」，例如「「週二晚上皮拉提斯」從 10/13（二）起的上課時間改為 19:30–20:30；地點改為 …。影響你報名的 3 堂，報名仍然有效…」。另一個做法是照每一場各發一則（學員報了 8 堂就收到 8 則）。

### 畫面

- 入口：系列場次的單堂詳情頁同樣顯示「修改課程」（取代「系列中的場次目前還不能修改內容」那句）。
- 改課頁最上方多一組「套用範圍」選擇：「只改這一場」／「改這一場和之後所有場次（共 N 場）」，預設「只改這一場」。
- 選「之後所有場次」時：日期欄改為唯讀說明（「每一場維持原本的日期」），「儲存前核對」列出會被修改的所有日期；提醒「之後生成的場次也會用新的設定」。
- 有人報名且改了時間或地點時，儲存前的確認視窗寫「會通知 X 位學員（共 Y 堂有人報名）」。
- 整批失敗時留在原頁保留輸入，錯誤指出是哪一天撞課或哪一天名額不足。
- 想改星期幾：在範圍選擇旁說明「要換星期，請用『從這場以後全部取消』再建立新系列」，連到系列頁。

### 測試規劃

只改一場（系列設定不變）、批次改（各場與系列設定都更新、之前的場次不動）、批次中一場撞課或名額不足時整批不寫且指出日期、之後生成的場次沿用新設定、系列頁各場名額分母正確、批次改與單場報名交錯不死鎖不超收、他人系列與暫停老師被拒、通知數量與內容（依 A 的決定）、UI 範圍切換與日期唯讀、RWD 三種寬度。

### 待產品主人確認

- **A. 通知數量**：每位學員一則（建議）／每一場各一則。
- **B. 範圍選擇的預設值**：「只改這一場」（建議，避免不小心改到整個系列）。
- **C. 入口**：沿用單堂詳情頁的「修改課程」（建議）；系列頁不另外加按鈕。
- **D. 「只改這場」可以改日期**（建議可以：放假那週挪到別天是常見需求；批次範圍仍不能改日期與星期）。
