# 08: 單堂頁：第一張卡內報名、同系列列表就地報名

來源：[spec Q1、Q4、Q5](../../../specs/member-inline-enroll-spec-draft.md)。

**What to build:** 沒報名的人在單堂頁，取消獨立的「報名這堂課程」卡（`ClassEnrollmentPanel`）與期班的合併報名卡（`TermClassEnrollPanel`）；第一張課程資訊卡標題下方放「我要報名」（需確認的課程為「申請報名」），按下後表單在這張卡內展開，期班的單堂頁在展開後先二選一（整期或只報這一堂）。手機底部固定「前往報名」列保留，按下去直接展開。「同系列的其他場次」每一列改用票 06 的共用列。備註一律用「加備註」。

**Blocked by:** 06

**Status:** 待開始

**Workflow mode:** STANDARD

**Human Gate:** no

**Risk flags:** 改動檔案最多，會更新較多舊測試；訪客登入引導與「只收整期」轉到期班頁的規則要維持。

- [ ] 第一張卡內的報名區：展開表單、登入選項、不能報名時的原因；期班二選一邏輯從 `TermClassEnrollPanel` 搬進來
- [ ] 刪除兩張獨立報名卡的渲染；手機底部「前往報名」帶 `enroll=1` 直接展開
- [ ] 同系列列表用共用列。持續開課且系列頁看得到時，上一批會把整張清單換成第一張卡的「查看這個課程的所有日期」連結：這條規則維持，因為系列頁的每一列在票 07 已可就地報名，入口沒有消失；測試要驗證這種情況下連結指向的系列頁確實有可報名的列。連結不成立時（混合系列、超過上限、系列頁看不到）清單維持列出並用共用列
- [ ] 單堂頁掛上 06 的共用回饋呈現：成功訊息在頁面頂部，失敗時第一張卡的表單維持展開或顯示原因
- [ ] 標題旁加期班標籤「期班・第 3 堂／共 8 堂」或「持續開課・每週四」，點擊到期班頁或系列頁（來自 `teacher-series-rollup-and-action-bar-spec.md` 2.3，學員端併在這張票；共用的「第幾堂」計算若該批票 01 尚未完成，先在本票做成共用函式供之後沿用）
- [ ] 更新依賴「報名這堂課程」卡標題的舊測試，覆蓋不減
- [ ] 測試：一般單堂、需確認、期班整期與單堂二選一、只能報整期、額滿、訪客登入回來展開、失敗後表單維持展開、手機 375px 無橫向溢出
