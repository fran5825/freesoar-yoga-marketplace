# 03: 申請表單區塊化與缺項提示（決策 3、4、5）

**What to build:** 申請表單維持單頁，分成數個卡片區塊；頂端顯示「還缺 N 項才能送審」；簡介與教學風格兩欄加範例文字與字數提示；非必填欄位（證照、價格區間、照片連結、偏好）標示「通過後再補也可以」。送審必填仍是現有 7 項，草稿機制不變，不合併欄位。

**Blocked by:** 02

**Status:** done（2026-09-25）

**Workflow mode:** STANDARD

**Human Gate:** no

**Risk flags:** 不改資料模型與必填清單（`requiredFields` 不變）；server-side 驗證維持權威

**實作紀錄：** 表單原本就分 4 個區塊，這票補的是：① 頂端即時顯示「還缺 N 項才能送審：…」（缺項名稱可點，跳到該欄位；補齊後變綠色「必填欄位都填好了，可以送出審核。」，措辭比照團主表單）；「檢查準備狀態」按鈕保留，按下會顯示欄位提醒並捲到第一個缺項。② 每個區塊標題旁顯示進度（必填 x / y、必填已完成、全部選填）。③ 簡介與教學風格加「參考寫法」與「已輸入 N 字」（只是字數顯示，沒有新增字數限制）。④ 選填欄位統一標「選填，通過後再補也可以」。必填清單與 server 驗證都沒動。手機截圖已看過：頁首說明文字偏長，表單要往下捲才看到，屬於後續可再調整的地方，這票沒動。

**後續補充（2026-09-25，產品主人決定）：** 「服務地區」改成只能勾選縣市，不再有「其他」自由輸入框（申請表單與 `/teacher/profile` 都是）；線上授課請在「授課形式」勾選。舊資料裡不在縣市清單的內容（例如 `ddde`）：可編輯時（草稿、被退回、老師資料頁）不再保留並顯示黃色提醒，且不算已填（要重新勾選才能送審）；審核中、已通過、已暫停維持原樣唯讀顯示。只改介面，後端驗證與資料庫沒動。簡介／教學風格內容太簡略（如 aaa、bbb）系統不偵測，交給管理員審核判斷（產品主人 2026-09-25 決定不做）。
