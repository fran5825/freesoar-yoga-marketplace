# 02：重複開課：每週固定與指定日期

**What to build:** 老師沿用單堂的單頁骨架，以每週固定或指定日期建立系列；建立前看懂實際場次，失敗後可直接修正。

**Blocked by:** 01 單堂開課：分區、摘要與錯誤保留（沿用已驗證的表單骨架、摘要與失敗保留機制）。

**Status:** draft

**Workflow mode:** STANDARD

**Human Gate:** yes

**Risk flags:** BRAND_RISK、LOW_PRESSURE_UX_RISK、SCOPE_DRIFT_RISK。

## 驗收條件

- [ ] 「每週固定／指定日期」清楚可見，選擇後顯示對應欄位；三模式切換保留各自輸入，單堂成功與失敗流程不回歸。
- [ ] 每週摘要顯示星期、既有起始規則、實際生成日期、時間與場次；指定日期摘要完整列出實際提交日期及時間，不以另一套排程算法產生核對內容。
- [ ] 摘要與提交結果一致，取代重複模式的泛用建立確認勾選，提醒課程建立後不能編輯；不增加新確認視窗。
- [ ] 重複 action 失敗保留全部場次輸入與明確錯誤，pending 防重送；未知結果不自動重試，不吞成功 redirect。
- [ ] 成功依既有規則建立系列與逐場 draft，進原系列詳情；場次仍不公開，不能將逐場開放報名稱為整系列公開。
- [ ] 起始日期、過去日期、場次上限、重複日期與時間衝突依既有驗證處理；拒絕情境不留下部分成功的場次。
- [ ] 離頁提醒與成功解除沿用 01，不增加持久草稿、自動儲存、系列公開、批次開放或排程新模式。
- [ ] outcome tests 覆蓋兩模式成功、失敗保留、摘要日期與結果相符、時間邊界；手機長日期清單不溢出，鍵盤能完成兩模式。

## 實作與驗證邊界

- 只整合既有系列建立 service／排程規則，不改 schema、state machine、權限、通知或生成 policy。
- 不依賴系列詳情改版；可用現有詳情驗收建立結果，不包含系列管理、列表與申請。
- 執行 diff whitespace、TypeScript、ESLint、build、系列建課／起始日期與單堂回歸 smoke，完成三種寬度 QA。
- rollback 僅回復本票 UI、action adapter、測試與描述；不刪除既有系列或場次。
- 實作需本票範圍核准；如需要 policy 變動，先停止並提出 HEAVY decision plan。
