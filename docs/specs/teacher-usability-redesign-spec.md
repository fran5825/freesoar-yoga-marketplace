## 1. 目標與範圍

讓老師用手機完成申請、建立課程、查看資訊與處理報名時，能清楚知道目前狀態與下一步，不必在不同頁面重新找資訊。

- 手機優先，電腦仍完整可用。
- 範圍：老師申請及登入後銜接、主動開課三種排程、我的課程、單堂詳情、系列詳情與必要總覽入口。
- 第一個畫面驗收里程碑：開課 → 詳情 → 開放報名／處理報名，分為 01–03 三票交付。
- 後續里程碑：列表與系列導覽、老師申請、最後整體驗收；不因開課優先而省略後續工作。
- 需求池與回應團主需求流程不重設；既有團主媒合課的讀取及操作資格維持。

## 2. 已確認的領域邊界

| 項目 | 保留的規則 |
| --- | --- |
| 老師申請 | 七項必填不減少；不需先儲存草稿才能送審；審核中唯讀，退回後可修正再送 |
| 建課資格 | 僅通過審核者可建立新課；資格及 ownership 仍由既有 service 檢查 |
| 課程建立 | 建立完整 `draft`，不是可離頁續編的未完成表單；建立後仍不能編輯內容 |
| 開放報名 | 維持明確的 `draft → open_for_enrollment`，不合併成建立即開放 |
| 公開瀏覽 | `isPublic` 與課程狀態不同；開放報名不自動改公開設定 |
| 非公開單堂 | 不列在訪客公開列表，但登入學員可使用既有課程連結；不宣稱為私密或指定名單可見 |
| 系列 | 每場獨立報名與處理；仍以不公開的場次生成，不加整系列發布／公開能力 |
| 取消系列 | 沿用既有可取消場次與連帶報名規則；不宣稱刪除系列或阻止往後生成 |
| 暫停老師 | 既有 own-scoped 課程讀取資格維持，補回我的課程入口；不新增建立或回應需求能力 |

不變更 Auth、session、Prisma schema、migration、role model、permissions 或 marketplace state machines。不新增課程編輯、套裝報名、批次審核、付款／退款、AI matching、原生 App、Wellness／Academy／Retreat 模組或完整老師 SaaS。

## 3. 共用畫面規則

- 沿用現有品牌色、字體與專區頁寬；不另建視覺系統。
- 老師頁使用一致的標題層級、說明位置、卡片間距、標籤與操作樣式。
- 頂端顯示狀態與重點；主要操作接近下一步，次要及取消操作獨立排列。
- 手機不靠橫向表格閱讀；長名稱、地址、備註能正常換行，按鈕不被擠出畫面。
- 提供可見鍵盤焦點、正確標籤與錯誤關聯；確認對話框應能以鍵盤操作、取消後返回原焦點。
- 成功、失敗與空狀態說明具體且溫和；不把未做的 email、審核時間或系列公開功能寫成承諾。
- 觸控操作目標至少 44px；在 375px、768px、1440px 檢查基本排版、長內容與主要操作。

## 4. 開課頁：已確認

畫面骨架：

```text
建立課程
[單堂] [每週固定] [指定日期]

課程內容
  名稱、課程風格、瑜伽類型
  課程說明（選填，預設收起）

時間地點
  此模式需要的日期／星期與場次
  開始、結束時間、地點、人數上限

報名設定
  是否列在公開課程列表
  是否需要老師確認報名

建立前核對摘要
  名稱、排程、日期、時間、地點、人數、報名設定
  建立後目前無法編輯內容；建立不會立即開放報名
[建立課程／建立課程系列]
```

- 預設單堂，三種排程入口可見；沿用 `single / weekly / fixed_dates`。
- 模式切換保留已填共用欄位及各模式資料。
- 地點、名額、是否需要確認報名仍帶入最近一堂老師開課的設定；未有上次資料時沿用現有預設。公開設定不擅自改成預設公開。
- 單堂公開設定顯示兩個清楚選項；系列的公開設定顯示既有限制，不提供無法生效的公開選項。
- 即時摘要取代目前「我確認以上資訊無誤」的泛用勾選，不新增另一道確認視窗；不影響學員報名的持久化 consent。
- 指定日期列出完整日期；每週固定至少顯示星期、起始規則、時間與建立場次。任何顯示的實際日期清單都必須與既有生成規則一致，不能另寫不同的計算規則。
- 必填、日期、時間、場次與衝突等底層驗證不放寬。錯誤顯示於相關欄位並有摘要，將焦點帶到第一個可修正處。
- 送出期間防止重複點擊；服務拒絕、驗證失敗及可恢復錯誤保留本次輸入，不用導回空白表單作為錯誤處理。
- 未完成輸入離頁時提醒；確認離開才捨棄。成功建立後的導向不應觸發未儲存提醒。沒有自動暫存／重新開啟恢復功能，文案不承諾續填。
- 成功後單堂進該堂詳情，系列進該系列詳情，沿用既有建立服務及回傳的 id。

## 5. 單堂詳情：已確認

- 頂端：名稱、來源、狀態、日期時間、地點、已報名／人數上限、待確認數。
- 下一步與對應操作放在一起。老師自建草稿顯示既有開放報名動作；有待確認報名時引導到名單；已結束可沿用既有標記完成規則。
- 草稿先核對課程內容；開放後先看報名名單；同一頁面骨架中按任務調整重點。已完成可查看評價，已取消仍可查看資料。
- 按鈕可用性與 backend 守門均沿用現有服務，不因移到頂端而開放團主專屬操作或暫停帳號的新能力。
- 待確認名單顯示學員與備註，逐筆確認／婉拒；確認直接執行。
- 婉拒確認顯示學員與課程；取消課程確認顯示課名、日期與連帶取消報名／通知的影響。取消系列亦須說明可受影響場次與既有規則。
- 取消操作放在獨立次要區；取消確認視窗預設焦點不放在破壞性按鈕。
- 公開可見性用實際資料顯示，不把不公開課程稱為私密。`draft` 不連到學員 route 稱為預覽。

## 6. 我的課程與系列：已確認

- 我的課程頂端有「＋ 建立課程」，電腦標題旁、手機標題下。資格不足時不提供可執行的新建操作。
- 預設近期課程，草稿、過往與全部入口清楚可見；具體分類與返回行為見第 8 節。
- 列表卡片顯示時間、地點、狀態、人數、待確認數與下一步，保留來源辨識。
- 系列詳情每場可點進單堂，顯示時間、狀態、已報名及待確認數；每場仍獨立處理，不新增批次狀態轉換。
- 系列資料計數只使用老師本人已有讀取資格的報名資料；查詢維持 ownership 範圍，其他老師的課／系列不可見。
- 系列創建成功訊息及詳情說清楚：逐堂開放報名，系列場次目前不在公開列表。

## 7. 老師申請：已確認

- 登入／申請的既有導向保留，不改 Auth；申請頁與老師專區標題、卡片層級一致。
- 七項必填集中：顯示名稱、簡介、教學風格、年資、擅長類型、服務地區、授課形式。
- 保留簡介／教學風格兩欄與參考寫法；地區仍依既有選項規則。
- 照片連結、證照、合作價格參考、教學偏好等選填收在「其他資料（可之後補）」。缺少選填不阻擋送審；有填但格式錯誤仍需提示與修正，錯誤區應展開。
- 儲存草稿為次要可選動作；送出審核是主要動作，不要求先存。保留二次送審確認並顯示實際摘要，移除重複的「檢查準備狀態」按鈕，改為即時缺項提示。
- 審核中唯讀內容與站內通知說明；不提供重複送審。
- 退回原因在最上方，必填與需要修正處易找到；修正後可依原服務再次送審。
- 通過與暫停者從申請頁進原老師總覽；暫停理由與資格限制保留，不把申請流程改成可立即開課。

| 問題 | 已確認的設計 |
| --- | --- |
| Q16 分類 | 即將上課含進行中、草稿獨立、過往含已結束未完成；全部含取消並可篩選 |
| Q17 返回 | 保留原列表／系列、篩選與位置；處理操作留同堂 |

| Q19 申請操作 | 即時缺項提示取代檢查按鈕；二次送審顯示實際摘要 |
| Q20 暫停老師 | 顯示既有我的課程查看入口，所有能力沿用原守門 |

Q16 具體條件：即將上課 `endAt > now` 且排除 `draft / cancelled / completed`，包含已開始尚未結束的課；草稿依狀態，不因時間過去移走；過往排除草稿與取消，包含 `endAt <= now` 或已完成。即將上課由近到遠、過往由新到舊。這些只是 UI 分類，不建立新 marketplace 狀態。

Q17 返回來源只允許本地老師課程列表與 own-scoped 系列及已知篩選參數，不接受任意 return URL；單堂從系列進來時優先回同系列，仍有我的課程入口。完成操作回饋不重複造成通知、頁面返回不重做 mutation。

Q19 草稿成功儲存只將本次送出的 snapshot 視為已存；途中繼續輸入的內容仍屬未存。送審成功轉唯讀且解除提醒；載入完成前或讀取／儲存 timeout 不顯示已存或誤判使用者改動。不新增申請自動儲存。

## 10. 驗收與測試草案

- TypeScript、ESLint、build；本輪只有文件，尚未執行程式 checks，也不宣稱畫面驗收通過。
- Playwright 使用獨立 `PORT=3100` 與先建置的伺服器，不借用使用者 dev server；日期用相對日期，避免過期 fixture。
- 三種排程切換保留資料；摘要與實際提交設定一致；缺項、時間與衝突拒絕保留輸入，不產生課程或意外公開。
- 成功建立／送審不跳未儲存提醒；失敗後不顯示成功；取消離頁提醒留在原表單，確認離開不承諾恢復。
- 單堂建立仍為草稿，開放報名才轉狀態；公開設定不被動修改；系列仍不公開且逐堂操作。
- 確認取消前不寫入；取消確認視窗能返回，實際取消仍依原服務通知並處理報名；不測「重複勾選」等鏡像實作的細節。
- 既有其他老師課／系列維持不可讀；團主媒合課不因 UI 位置而取得老師自建課專屬操作。
- 七項必填、選填錯誤、直接送審、已送審唯讀、退回修正、通過／暫停導向均保留。
- 列表切片驗證分類時間邊界、返回上下文、系列場次 counts 與暫停入口；不把先完成第一片稱為全部完成。
- 375px／768px／1440px、鍵盤焦點、長名稱與地址、多筆報名、空列表、錯誤、審核中／退回狀態均需畫面檢查。
- 所有必要檢查後提供 changed files、checks、self review、scope drift 與 review packet；不 auto commit、push、deploy 或發布任何課程。
