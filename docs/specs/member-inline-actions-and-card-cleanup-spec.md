# 學員頁面：就地請假與精簡卡片 Spec

建立日期：2026-10-10。來源：產品主人 `/grill-with-docs`（Q1–Q5 全部照建議確認）。這是畫面整理與 server action 串接，**不動 schema、權限、state machine**，規則沿用 [重新報名與取消請假 spec](./enrollment-re-enrollment-spec.md)。

## 1. 要解決的問題

學員要請假或退出整期，得在「我的報名」頁點進單堂頁、或換到期班頁，兩段式操作；單堂頁的「你的報名狀態」卡很占空間；各總覽即使沒有待處理事項也放一張寫「目前沒有待處理事項」的空卡。

## 2. 決策

| # | 決策 |
|---|------|
| I1 | 請假、取消請假、退出整期都「就地」操作：按鈕在狀態旁，按下去在原處展開確認，不換頁 |
| I2 | 「我的報名」頁整期卡：每一堂那一列有狀態標籤與請假按鈕；卡片底部有「退出整期」按鈕；拿掉「某一堂不能來…請到期班頁」那行字；「查看每一堂」預設收合，退出整期按鈕在收合區外面 |
| I3 | 期班頁版面不動，只在「查看每一堂」每一列的已報名標籤旁加請假按鈕（退出整期維持現在位置）；原本「到查看每一堂點進那一堂按請假這一堂」的說明改成「到查看每一堂，按那一堂的請假」 |
| I4 | 單堂頁「同系列的其他場次」：整期學員自己的每一列顯示狀態標籤與請假按鈕；已請假的列顯示「請假中」與「取消請假」按鈕，都就地操作 |
| I5 | 三處共用同一個元件，文案依期班報名方式（`term_only`／`term_and_single`）切換，規則與 `enrollment-re-enrollment` spec 4.3、4.6 相同 |
| I6 | 單堂頁拿掉「你的報名狀態」卡：狀態標籤與原因文字放進第一張課程資訊卡；單堂課的取消報名、重新報名（含備註與同意勾選）與整期請假、取消請假，做成第一張卡內的按鈕，就地展開 |
| I7 | 沒報名的人看到的「報名這堂課程」卡維持原樣（主要動作） |
| I8 | 持續開課的單堂頁（**對所有使用者適用，含訪客與非整期學員**），「同系列的其他場次」整張卡改成第一張卡裡一行連結「查看這個課程的所有日期」，連到系列頁；**系列頁看不到時**（判斷條件與系列頁 `getPublicSeriesDetail` 完全相同：系列是持續開課，且至少有一場未來、公開、狀態符合、老師 `approved` 的場次）維持列日期。**混合系列例外**：同一個持續開課系列可以同時有公開與非公開場次（單場可各自設定公開），已登入學員的「同系列的其他場次」現在會列出兩者，但系列頁只列公開場次；因此只有在「這位使用者看得到的其他場次全部都是公開場次，且連同這一堂的場次總數沒有超過系列頁的顯示上限（200 堂，見 `SERIES_SHOW_MAX`）」時才用連結取代列表，否則（含非公開場次）維持列日期，不讓任何日期失去入口。訪客只看得到公開場次，因此恆為連結。期班維持列表（要放 I4 的按鈕） |
| I9 | 「我的報名」頁整期區的小標題「整期報名」拿掉（與卡片標題重複） |
| I10 | 「待你處理」卡：沒有「輪到自己處理」的事項時整張不出現；有事項時是頁面第一張卡（在頁面標題與提示橫幅之後）。套用到學員、老師、團主、管理員四個總覽與「我的報名」頁。「等待對方回覆」「等老師確認」不算待你處理：學員、團主本來就是獨立卡片，維持現狀；**老師總覽目前把等待事項（`waiting`）和待處理事項（`action`）放在同一張卡，改成拆開**：「待你處理」只放 `action`，`waiting` 放進緊接在後的「等待對方回覆」卡，兩張都在沒事項時不出現。管理員沒有待審項目時，最上面直接是數字統計 |

### 檢視後確認「已經是現況」的項目（不用改）

- 期班頁的整期報名區已在第一張課程資訊卡裡（`teacher-class-scheduling` 票 14），「你的整期報名」與「每一堂」維持現有兩塊，不合併（產品主人要求期班頁維持一樣）。
- 單堂頁與期班頁的課程說明、適合對象、準備事項已經是「有填才顯示」（`ClassInfoSections`）。
- 老師總覽與管理員總覽的「待你處理」本來就是第一張卡，只需要在沒事項時隱藏。

## 3. 規則

### 3.1 就地操作的共用元件

一列（整期的某一堂）依資料顯示：

| 這一列的狀態 | 顯示 |
|--------------|------|
| 有效（`pending`／`confirmed`）、尚未開始 | 狀態標籤＋「請假」按鈕（展開：依模式的說明文字、確認勾選、「確認請假」） |
| 學員請假中且可取消請假（`leave_available`） | 「請假中」標籤＋「取消請假」按鈕（一鍵，不需要確認勾選，同現有） |
| 請假中但名額被報滿（`leave_full`，`term_and_single`） | 「請假中」標籤＋「這一堂名額已被報滿，請聯絡老師」，沒有按鈕 |
| 請假中但不能取消請假（整期已退出／被婉拒、課程已開始、老師非 approved） | 「請假中」標籤＋對應原因文字，沒有按鈕 |
| 課程已開始或已結束 | 只有狀態，沒有按鈕 |

按鈕的判斷依據分兩種，都在 service layer／共用函式算好，頁面只依結果顯示：

- **有效的報名（`pending`／`confirmed`）能不能請假**：沿用 `cancelOwnEnrollment` 的資格——是本人的、整期仍有效、課程沒取消也沒完成、`startAt` 尚未到達。`getReEnrollState` 對有效報名只回傳 `not_cancelled`，不能拿來判斷這一項。
- **已請假的列能不能取消請假**：`getReEnrollState`（`enrollment-re-enrollment` spec 4.6）。

每一列需要的資料（報名狀態、取消者、整期報名狀態、占用名額、期班報名方式、老師狀態、課程時間與狀態）在各頁的讀取函式一併帶出。

請假文案：
- `term_only`：「請假後，這一堂會標示為請假；整期的其他堂照常。開課前可以取消請假。」
- `term_and_single`：「請假後，這一堂的名額會開放給單堂報名；整期的其他堂照常。開課前、名額還在時可以取消請假。」

### 3.2 操作後回到哪裡

每個動作做完回到「按下的那一頁」，並顯示結果訊息（成功或失敗原因），沿用既有的 `result`／`message` 回饋慣例；不跳到別的頁面。請假與取消請假的長列表定位：回傳網址帶 `open=sessions` 與 `focus` 參數（成功 `focus=session-row-<報名 id>`、失敗 `focus=action-feedback`；server action 的 redirect 不保留網址 fragment，所以用參數，頁面進來後捲到目標），頁面看到 `open=sessions` 就把「查看每一堂」保持展開。**成功**時捲到剛操作的那一列，使用者能確認剛操作的是哪一堂；**失敗**（例如送出前名額被占滿）時列的狀態沒變，改捲到可見的結果訊息區（`id="action-feedback"`，維持 `aria-live`），不捲到列，確保使用者看得到失敗原因。**退出整期例外**：成功後整期卡（「我的報名」）消失、期班頁的退出按鈕不屬於某一堂，所以退出整期只回到同一頁並顯示結果訊息（例如「已退出整期，取消了之後的 N 堂」），不帶 `open=sessions` 與 `focus` 參數；失敗時整期卡與按鈕仍在，同樣只顯示訊息。伺服器端規則、本人檢查與鎖不變，仍在既有的 `cancelOwnEnrollment`、`restoreOwnLeave`、`withdrawOwnSeriesEnrollment`。

### 3.3 「我的報名」頁整期卡

- 整期卡的每一堂列表包含：即將上課且有效的堂，以及該整期仍有效時請假中的堂（目前請假中的堂掉到下方「過去與已取消」逐場列出，要移進整期卡，避免重複）。
- 卡片底部「退出整期」按鈕，展開內容同期班頁的退出整期（會取消的堂數與日期、已上過的紀錄保留、確認勾選、「確認退出整期」）。
- 整期已退出或被婉拒後，該期不再有整期卡，已取消的堂照現狀逐場列在「過去與已取消」。

### 3.4 單堂頁第一張卡

- 卡片標題列：狀態標籤（已報名、等待老師確認、請假中、已取消）與原因文字（例如「老師婉拒了這次報名，無法重新報名」）。
- 動作列（依 `getReEnrollState`／既有取消規則）：單堂：取消報名；已取消可重新報名：重新報名（展開備註、基本同意、按鈕；需老師確認的課按鈕為「重新送出報名申請」）；整期：請假、取消請假。不能時只顯示原因，沒有按鈕。
- 原「你的報名狀態」卡整張移除；沒報名的人看到的「報名這堂課程」卡不變。

### 3.5 待你處理

- 各總覽「輪到自己處理」的事項（老師 `todoItems` 中 `kind = action`、團主 `pendingActions` 與 `proposalActions`、學員 `review`、管理員 `pending`）為空時，整張卡不渲染，不留空標題或空訊息；`waiting` 類事項不影響「待你處理」卡是否出現。
- 學員總覽把「待你處理」移到快速入口卡之前，成為標題後第一張卡。

## 4. 實作切片（見 `docs/superpowers/plans/inline-member-actions/ticket-breakdown.md`）

1. 共用就地元件與資料，並先用在「我的報名」頁整期卡。
2. 期班頁每一堂列的請假按鈕。
3. 單堂頁第一張卡（狀態與動作）、同系列列表按鈕、持續開課連結。
4. 「待你處理」隱藏與位置。
5. 驗收與文件同步。

## 5. 不在範圍

候補、請假原因欄位、管理員代操作、變更期班頁其他版面、任何 schema、權限、狀態機調整。

## 6. 風險

| 風險 | 處理 |
|------|------|
| 就地展開的表單在手機被截或溢出 | 每個展開畫面都跑 375px 寬度的橫向溢出檢查 |
| 按鈕的顯示條件與伺服器規則不一致，出現送出必失敗的按鈕 | 顯示條件全部走 `getReEnrollState`／既有規則；測試涵蓋名額被報滿、整期已退出等情況 |
| 多處各寫一份請假表單，文案與行為不一致 | 共用同一個元件與同一組 server action 包裝 |
| 持續開課連結到不公開的系列頁會 404 | 只在系列公開時顯示連結，否則維持列日期 |
| 舊測試依賴「你的報名狀態」卡與「請假這一堂…」文字 | 逐一更新並保持相同覆蓋；改動集中在第 3 張票 |
