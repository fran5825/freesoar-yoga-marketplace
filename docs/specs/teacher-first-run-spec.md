# 老師第一次使用：從通過審核到第一位學員報名：spec

建立日期：2026-10-24。來源：`/feature-loop` 的 `grill-with-docs`（2026-10-24，Q1–Q13 產品主人確認）；問題清單見 `docs/superpowers/plans/teacher-experience-walkthrough/2026-10-24-first-time-teacher-walkthrough.md`（下文 F# 指該報告的發現編號）。相關 ADR：無新增；沿用 [ADR 0008](../adr/0008-notification-series-grouping.md) 的通知系列合併。名詞見 `docs/context/glossary.md` 的「開始使用」「團體需求」「僅透過連結招募」「老師公開頁」。

## Problem Statement

飛索要先從老師開發（glossary「老師先行試營運」）。老師加入後，應該只用這個網站就能管理日常教學，而且不用人教就學得會。走查發現，開課、分享、收報名、收款紀錄這些功能大多已經有了，問題出在**老師不知道下一步、幾個預設值讓學員端卡住、關鍵時刻沒有通知**：

- 剛通過審核、還沒有課時，總覽沒有任何「下一步」（F1）；通過通知只說「可以回應需求」，連到可授課時間頁（F2）。
- 老師開課預設「僅透過連結招募」，沒登入的學員點 LINE 連結只看到「登入後查看這堂課」（F3）。
- 「報名送出即成立」的課有人報名，老師收不到通知；學員自己取消，老師也不知道（F4）。
- 審核中什麼都不能做，也不知道通過後要做什麼（F5）。
- 開放報名前沒提醒填收款資訊；學員報名時拿到的收款快照是空的，之後補填也不會更新（F6）。
- 單堂課一定要「建立草稿 → 再按開放報名」兩步，系列卻可以建立後直接開放（F8）。
- 老師公開頁的開關藏在「照片」分頁（F9）。
- 有新的團體需求，老師不會知道；導覽列叫「需求池」、頁面叫「團體需求」，空畫面還寫「沒有符合條件的需求」（F11）。
- 退回申請的通知語氣像結案，頁面卻寫可以修改後重新送出（F13）。

## Solution

讓剛通過審核的老師，順著畫面就能走到「第一位學員報名、老師也知道」：

1. 通過通知與總覽改成帶老師「開始使用」：填收款與聯絡 → 開第一堂課 → 公開我的老師頁。
2. 老師開的第一堂課預設列在公開列表；單堂也能建立後直接開放報名，預設直接開放。
3. 開放報名前，缺收款資訊就提醒。
4. 有人報名、有人自己取消，老師都會收到站內通知，點了直達那堂課或那個系列。
5. 有新的團體需求公開，已通過的老師都會收到站內通知。
6. 審核中畫面說明通過後要做的三件事；退回通知改成「可修正」的語氣。
7. 「需求池」統一改叫「團體需求」，空畫面說明為什麼是空的。

## User Stories

開始使用與通過通知

1. 身為剛通過審核的老師，我想在通過通知裡看到「現在可以開自己的課，也可以回應團體需求」，讓我知道通過後能做什麼。
2. 身為剛通過審核的老師，我想點通過通知就到老師總覽，不要被帶到可授課時間頁。
3. 身為剛通過審核、還沒開課的老師，我想在總覽最上方看到「開始使用」，列出三步和各自的按鈕，讓我不用自己找下一步。
4. 身為老師，我想每完成一步，那一步就自動打勾，不用自己回報。
5. 身為老師，我想看到「公開我的老師頁」這一步是可以跳過的，讓我知道它不是必要的。
6. 身為老師，我想在三步都完成後，「開始使用」自動收起來，讓總覽回到日常的「待你處理」。
7. 身為不想照步驟走的老師，我想按「先不用」把「開始使用」收起來，而且之後不會再出現。
8. 身為老師，我想在「開始使用」下方看到「看看團體需求」，讓我知道也可以接團體的案子。
9. 身為暫停中的老師，我不應該看到「開始使用」，因為我不能開新課。

審核中與退回

10. 身為審核中的老師，我想在申請狀態頁看到「通過後你會先做的三件事」，讓等待有方向。
11. 身為申請被退回的老師，我想在通知裡看到「需要補充的地方」和「修改後可以重新送出」，而不是像被拒絕一樣的語氣。

預設公開與建立後直接開放

12. 身為第一次開課的老師，我想課程預設就列在公開列表，讓學員點我的連結不用先登入就看得到時間、地點、費用。
13. 身為老師，我想在「公開列表」選項旁看到白話說明：選「僅透過連結招募」時，學員要先登入才看得到課程內容。
14. 身為上一堂課選了「僅透過連結招募」的老師，我想下次開課沿用我上次的選擇，不要每次都被改回公開。
15. 身為已經有課的老師，我不希望這次改版讓我既有的課突然變公開。
16. 身為開單堂課的老師，我想選「建立後直接開放報名」，預設就是這個，讓我少一步。
17. 身為想先檢查再開放的老師，我想改選「先存成草稿」，之後再到課程頁按「開放報名」。
18. 身為建立後直接開放的老師，我想建好就看到「已開放報名。下一步：把報名連結傳給學員」，並且有複製連結的按鈕。
19. 身為建立系列課的老師，我想系列的「公開列表」預設也比照單堂（第一堂預設公開，之後沿用上次選擇）。

收款提醒

20. 身為還沒填收款帳號的老師，我想在開放報名之前看到提醒，告訴我「學員報名時會看到你當下填的收款資訊，之後補填不會更新給已報名的人」，並附連結到「收款與聯絡」。
21. 身為只填了收款規則、沒填帳號的老師，我也想看到「還沒填收款帳號」的提醒。
22. 身為現金收費或免費開課的老師，我想能直接略過提醒、照樣開放報名，提醒不擋操作。
23. 身為老師，不論我是用單堂課頁的「開放報名」、建立時直接開放、系列「全部開放」、系列單場的快速開放，還是「生成更多」時直接開放，都應該在按下之前看到同樣的提醒。

報名與取消通知

24. 身為開「報名送出即成立」單堂課的老師，我想有人報名時收到站內通知「『課名』有新的報名」，點了到那堂課的老師頁。
25. 身為開期班的老師，我想有人整期報名時收到一則站內通知，點了到那個系列的老師頁。
26. 身為老師，我想學員自己取消單堂報名時收到站內通知，點了到那堂課。
27. 身為老師，我想學員退出整期時收到站內通知，點了到那個系列。
28. 身為同時也是學員的老師，我以學員身分報名別人的課時，收到的學員通知要跟改版前完全一樣（同樣的文案、同樣的目的地，包括系列通知照 ADR 0008 導到期班頁或系列頁），不能因為我也是老師就被帶到老師頁面。
29. 身為老師，我想同一個系列同一天的多則報名通知照現有規則合併成一則，不被洗版（ADR 0008）。
30. 身為「需要我確認」的課的老師，我收到的「有新的報名待確認」維持現狀，不會多收一則重複的通知。

團體需求

31. 身為已通過的老師，我想在有新的團體需求公開時收到站內通知，點了到「團體需求」頁。
32. 身為同時是團主的老師，我發起的需求公開時，我只收到團主那則「你的需求已公開」，不會再收到給老師的那則。
33. 身為暫停中、審核中或被退回的老師，我不應該收到新需求通知。
34. 身為老師，我想導覽列和頁面標題都叫「團體需求」，不要一個叫需求池、一個叫團體需求。
35. 身為看到空的團體需求頁的老師，我想知道為什麼是空的（需求要經過平台審核才公開、目前大新竹地區數量還不多），也知道有新需求時會收到通知。

老師公開頁

36. 身為老師，我想在「老師資料 › 個人資料」分頁找到「公開我的老師頁」開關，而不是在「照片」分頁。
37. 身為老師，我想在「開始使用」看到「公開我的老師頁」並一鍵前往設定。
38. 身為已經打開或關閉公開頁的老師，我的設定在改版後維持不變。

## Implementation Decisions

### 開始使用（F1、F9、Q10）

- 新增「開始使用」區塊，放在老師總覽最上方（在「待你處理」之上），只給 `approved` 的老師看；`suspended`、未通過的老師都不顯示。
- 三步與完成條件都從既有資料判斷，不新增欄位：
  1. 填收款與聯絡：`paymentAccountInfo` 有內容（trim 後非空）。
  2. 開第一堂課：老師有任何一堂自己的課（任何狀態都算）。
  3. 公開我的老師頁（標示「可跳過」）：`isPublicPageEnabled` 為 true。
- 每一步顯示狀態與前往按鈕；完成的打勾。下方放「看看團體需求」次要連結。
- 收起條件：三步都完成，或老師按「先不用」。「先不用」要跨裝置記住，但不能新增 schema 欄位：**判斷方式由切票時查證**，優先順序是 (a) 沿用既有可存放老師偏好的欄位或資料；(b) 若沒有，改成「1、2 兩步完成就自動收起，『先不用』只在本次瀏覽器記住」，並在票裡註明。不得為此新增欄位。
- 判斷邏輯放在 domain 層（比照既有 `buildTeacherTodoItems`），頁面元件只負責顯示。

### 通過通知、審核中、退回（F2、F5、F13）

- `teacher_application_approved` 的文案改成同時提到「開自己的課」與「回應團體需求」；連結從老師資料改到老師總覽。
- 審核中（`submitted`）的申請狀態畫面加「通過後你會先做的三件事」，內容與「開始使用」三步一致（只是說明，不能操作）。審核中仍不能編輯老師資料各分頁（Q3：權限不變）。
- `teacher_application_rejected` 的文案改成「需要補充」與「修改後可以重新送出」的語氣，原因照舊附上。

### 預設公開（F3、Q1、Q8）

- 老師開課（單堂與系列）在**沒有上一堂課可沿用**時，「公開列表」預設改為列在公開列表。有上一堂課時，沿用上一堂的選擇。
- **注意：沿用公開設定目前並不存在**。既有的「沿用上一堂」只帶地點、名額與報名審核設定，沒有 `isPublic`。要在「讀取上一堂預設值」的查詢與型別加入 `isPublic`，表單接收後帶入，並保留明確的 `false`（上一堂選了僅透過連結招募，這次就預設僅透過連結招募）。單堂與系列都要能沿用兩種選擇。
- 已建立的課程一律不變；不跑資料轉換。
- 「公開列表」選項加白話說明：選「僅透過連結招募」時，學員要先登入才看得到課程內容。分享文案的「需要先登入」那句只在課程是「僅透過連結招募」時出現。
- 權限規則不變：訪客仍只能看到 `isPublic = true` 的課（`docs/domain/permissions.md`）。
- 這條取代 `teacher-class-scheduling-spec.md` 中「系列預設僅透過連結招募」的預設值；該 spec 同步加註。團主開的團體課不受影響。

### 單堂建立後直接開放（F8、Q4）

- 單堂建課表單加入與系列相同的「建立後直接開放報名／先存成草稿」選項，預設「建立後直接開放報名」。
- 狀態機不變：仍是 `draft → open_for_enrollment`，只是在建立的同一個操作裡完成，權限檢查沿用既有開放報名的 service。開放失敗時課程保留為草稿，並告訴老師原因。
- 這條取代 `docs/teacher-usability-plan.md` 2026-10-03 定案的 Q6（「建立 → 詳情 → 開放報名」）；理由是現在已有改課功能，建立後仍可修改。該文件同步加註。
- 開放後的回饋與下一步文字改成「已開放報名。下一步：把報名連結傳給學員」，並在 0 人報名時維持同樣的下一步。

### 收款提醒（F6）

- 收款帳號（`paymentAccountInfo`）與收款規則（`paymentRulesText`）分開檢查，缺哪個就提醒哪個，並連到「收款與聯絡」。只填規則、沒填帳號也要提醒帳號。
- 提醒說明快照行為：學員報名時拿到當下的收款資訊，事後補填不會更新給已報名的人。
- 提醒不擋操作，可直接繼續（現金、免費課程）。
- 涵蓋**所有會讓課程開始收報名的入口**，並出現在按下之前：單堂課頁的「開放報名」、單堂建立時直接開放、系列建立時「建立後全部開放報名」、系列頁「全部開放」、系列頁單場的快速「開放報名」、系列「生成更多」時直接開放、期班「追加補課」在剩餘場次都已開放時直接建立開放中的補課。切票時先搜尋程式中所有會把課程改成 `open_for_enrollment` 的老師端操作，確認清單完整。
- 判斷邏輯放在 domain 層一個共用函式，各入口共用。

### 報名與取消通知老師（F4、Q2、Q7、Q13）

- 「報名送出即成立」的單堂報名：沿用 `enrollment_confirmed` 事件，新增給老師（`counterpart`）的收件人與文案，帶 `teacher_class_session` target。學員（`self`）的通知、連結與系列合併行為**完全不變**；老師那一則的連結分兩種情況：**單則**（沒有被合併）用它自己的 target，直達那堂課或那個系列；**合併後**（同一系列同一天多則，ADR 0008）照 ADR 0008 連到老師的系列管理頁，沿用既有的系列連結判斷（它已會核對收件人是不是該系列的授課老師），不能只用最新一則的 target，否則只會連到其中一堂。驗證要涵蓋單則、合併後、以及同時是老師與學員的帳號。
- 整期報名：同一事件，給老師的通知帶新的 `teacher_class_series` target（見下方 schema），一筆整期報名只發一則。
- 學員自己取消單堂報名：沿用 `enrollment_cancelled`，新增給老師的收件人與文案，帶 `teacher_class_session` target。
- 學員退出整期：沿用既有退出整期的事件，新增給老師的通知，帶 `teacher_class_series` target。實作時先查證退出整期目前用哪個通知類型。
- 老師或管理員主動婉拒、取消時，不再額外通知老師本人（是他自己做的）。
- 老師報名自己的課（如果允許）不通知自己。
- 只發站內通知；`EMAIL_POLICY` 不加老師（`counterpart`）。
- 「需要我確認」的課維持既有 `enrollment_pending_review`，不重複發。
- 系列合併照 ADR 0008：通知帶系列 id，通知頁照既有規則合併。

### 新團體需求通知老師（F11、Q6、Q12）

- 新增通知類型（暫名 `demand_request_available`），在需求被管理員核准公開的同一個時點發出，收件人是所有 `approved` 的老師，**排除**發起這筆需求的團主本人。
- 連結：依新類型固定導到老師的「團體需求」頁，不需要 target。
- 只發站內通知：在 `EMAIL_POLICY` 為新類型加一筆空陣列（policy 是完整對照表，少一筆會讓 TypeScript 報錯）。
- 發送失敗不影響需求公開（沿用既有「通知失敗被吞掉、只記 log」的模式）。

### 團體需求名稱與空畫面（F11、Q9）

- 老師導覽列「需求池」改為「團體需求」；頁面標題維持「團體需求」。
- 空畫面拿掉「符合條件」，說明需求要經過平台審核才公開、目前大新竹地區數量還不多，並告知有新需求時會收到通知。

### 老師公開頁開關（F9、Q5）

- 「公開我的老師頁」開關從「照片」分頁搬到「個人資料」分頁；預設值不變（關閉）、既有設定不變。「照片」分頁留一行說明連到新位置。

### Schema 變更（需產品主人確認：已於 2026-10-24 Q12、Q13 確認）

只新增 enum 值，不改、不刪任何欄位或資料：

- `NotificationType` 新增一個值（暫名 `demand_request_available`）。
- `NotificationTargetType` 新增 `teacher_class_series`，`link.ts` 的白名單對應到老師的系列頁。

依 `docs/harness/risk-based-workflow.md`，這兩項屬 HEAVY：在獨立 worktree、用獨立測試資料庫做，不碰本機開發資料庫。`docs/domain/data-model.md` 與通知相關文件同步更新。

## Testing Decisions

- 好的測試只驗外部行為：使用者看到什麼、點了到哪裡、誰收到通知、資料庫狀態是否正確；不驗內部函式怎麼寫。
- 專案目前只有 Playwright smoke test（`npm run test:smoke`，`tests/smoke/`），本 spec 沿用，不新增測試工具。
- 測試 seam（由高到低）：
