# 系列收合、操作列與通知合併：spec

建立日期：2026-10-11。來源：`/grill-with-docs`（2026-10-11，Q1–Q22，產品主人全部採用建議，Q4 選方案 C、Q9 與 Q18 依產品主人補充調整）。相關決策：[ADR 0008](../adr/0008-notification-series-grouping.md)。名詞見 `docs/context/glossary.md` 的「系列卡」。

## 1. 目標

1. **同系列只顯示一個**：老師「我的課程」、管理員課程清單、通知，一個課程系列（期班或持續開課）只出現一次；單場操作到系列頁或單堂頁再做。
2. **按鈕集中、說明不佔版面**：單堂頁的按鈕集中在標題下方一排，說明改放進確認視窗或「ⓘ」，不再平鋪。
3. **期班一眼看得出來**：單堂頁標題旁明確標出「期班・第 3 堂／共 8 堂」。
4. **繳費狀況一眼看懂**：報名名單一位學員一排，付款標籤、轉帳備註、按鈕在同一排。

## 2. 已決定的規則

### 2.1 系列卡（Q1、Q2、Q13、Q14、Q15）

- 老師「我的課程」：屬於系列的場次收合成一張系列卡；單堂獨立的課維持一場一張卡。期班與持續開課都收合。
- 系列卡內容：標題、「期班・共 N 堂」或「持續開課」標籤、上課時間、地點、下一堂日期、已報名與待確認人數。點整張卡進入系列管理頁（`/teacher/classes/series/[id]`）。
- **人數一律算不重複學員**：整期報名會在每一堂各有一筆報名，同一位學員報 8 堂只算 1 位。已報名＝該分頁內場次有 `confirmed` 報名的不重複學員；待確認＝有 `pending` 報名的不重複學員（整期待確認也只算 1 位）。
- 四個分頁（即將上課、草稿、過往、全部）：系列只要有任一場屬於該分頁就出現一次；卡上的堂數與人數只算該分頁內的場次（例如「草稿」分頁寫「3 堂草稿」）。
- 卡片底部只顯示**最急的一件待處理**，順序沿用老師總覽「待你處理」：待確認 > 已結束待標記完成 > 草稿待開放。例如「3 人待確認 →」；都沒有則顯示「開放報名中」等狀態。
- 管理員課程清單：同樣收合成系列卡，連到新增的**管理員唯讀系列頁**（列出每場日期、狀態、人數，點一場進入管理員既有單堂頁）。讀取用管理員專用查詢，不共用老師 own-scoped 查詢；權限需 security review。
- 團主課程清單：目前不會出現系列場次（系列只有老師能建），不改。

### 2.2 快速按鈕與操作列（Q3、Q5、Q8、Q9、Q18、Q20）

**規則：每個狀態最多兩顆常駐按鈕——一顆依狀態，一顆該狀態最常用；其他功能攤開或收進「更多」。**

老師的按鈕表：

| 狀態 | 第一顆（實心主色） | 第二顆（淡色外框） |
|---|---|---|
| 草稿 | 開放報名 | 修改課程 |
| 開放報名中、尚未開始 | 複製報名連結 | 取消課程 |
| 已結束、待標記完成 | 標記完成 | 無 |
| 其他 | 無 | 無 |

- 「開放報名中」把複製報名連結放前、取消課程放後（Q20 對調），避免最顯眼的是不可逆操作。
- **單堂頁**：兩顆放在標題下方。其餘（修改課程、從這場以後全部取消等）在版面夠寬時攤開成同一排，手機放不下時收進「更多」選單。
- **系列管理頁每一列**：只放一顆依狀態的動作（草稿＝開放報名、開放中＝取消課程、已結束＝標記完成），「N 人待確認」為文字連結。其他單場操作點進單堂頁。系列頁既有的整批操作（全部開放報名、追加補課、生成更多、取消整個系列）維持。
- **說明不平鋪**：「分享給學員」「取消這堂課」兩個獨立區塊移除。不可逆操作的說明放在確認視窗（沿用 `ConfirmActionDialog`，內容已有影響人數）；需要一眼看懂的才在按鈕旁放「ⓘ」，點開顯示一兩句。
- 待確認報名的「確認報名／婉拒」維持在報名名單裡逐位操作（每位學員各自決定，不能省）；整期報名仍到系列頁一次處理。
- **套用範圍與角色別按鈕**（只用各角色**現有**的 action，不新增權限）：
  - 老師單堂頁、老師系列管理頁：上表。
  - 團主單堂頁：草稿＝開放報名（第二顆無，團主沒有改課功能）；開放中＝複製報名連結（沿用 `ClassShareLink`）＋取消課程；已結束＝標記完成。
  - 管理員單堂頁：管理員只有「取消課程」，可取消時它是唯一一顆（淡色外框），其他狀態沒有快速按鈕；報名名單的付款與取消報名維持逐位操作。
  - 共用函式依「角色＋狀態＋該角色可用的 action」產生按鈕，角色沒有的 action 一律不出現。
- 「標記完成」仍需手動（系統不會自動完成，學員評價邀請依它觸發）；改成自動完成會動 state machine，不在本 spec，列入 `docs/backlog.md`。

### 2.3 期班標籤（Q6、Q18）

- 單堂頁標題旁：期班顯示「期班・第 3 堂／共 8 堂」，持續開課顯示「持續開課・每週四」（指定日期的持續開課顯示「持續開課」）；點擊進入該身分的系列頁。取代現有的「系列：…」標籤。
- 「第幾堂／共幾堂」以未取消的場次依上課時間排序計算。
- 套用：老師單堂頁、管理員單堂頁、學員單堂頁（學員端併入 `inline-member-enroll` 票 08，避免兩批同時改同一頁）。

### 2.4 報名名單一排排版（Q7、Q19）

- 每位學員一排：姓名、付款標籤（待付款／已收款／已退款）、轉帳備註，按鈕（標記已收款或標記已退款）放在同一排最右邊；手機寬度不夠時按鈕換到下一排。收款備註與退款說明有填時顯示在下一行。
- 「整期／單堂」標籤：整期學員不加標籤（頁首已標明期班）；只有在「整期和單堂都收」（`term_and_single`）的期班裡，單堂報名的學員加「單堂」標籤；只收整期的期班完全不顯示。
- 套用：老師單堂頁的已報名名單與待確認名單、「已取消但有付款紀錄」、老師系列管理頁的整期學員名單。
- 管理員單堂頁的報名名單也有付款與取消按鈕，依「套用整站」原則同樣改成一排（產品主人未逐項點名，實作前在票內確認一次）。

### 2.5 通知合併（Q4＝C、Q10、Q11、Q12、Q16、Q17；細節見 ADR 0008）

- `Notification` 新增可為空的 `recurringClassSeriesId`（`onDelete: SetNull`）與索引；課程相關通知在該課屬於系列時寫入。
- **批次動作源頭只發一則**（站內與 email 都是）：建立系列、生成更多場次、取消整個系列、從這場以後全部取消。內文：「『X』共 8 堂（10/15–12/03）」。修改整個系列目前已是每位受影響學員一則，只補系列 ID 與堂數文字。
- **顯示時合併**：同一位收件人、同類型、同系列、同一天（台北時間）合成一則，標示則數與最新時間。
- 合併後的一則（以及批次動作的單一通知與其 email）連結由 server 依收件人與系列推導，不存網址、不靠身分旗標：
  - 收件人是該系列的授課老師 → 老師系列管理頁。
  - 其他收件人（學員）：期班 → 期班頁 `/classes/terms/[id]`（看不到時該頁已有「目前看不到這個期班」說明，不是 404）；持續開課 → 學員系列頁 `/classes/series/[id]`，**只有該頁對學員可見時**（同 `getPublicSeriesDetail` 條件：公開、有未來場次）才用，否則退回「我的報名」`/member/enrollments`。
  - 團主目前不會收到系列通知；若收到則沿用既有單筆連結規則。
- 舊通知不補系列 ID，維持原樣。

## 3. 不變的規則

- 不改任何 state machine、狀態轉換條件、報名或付款驗證；按鈕的可用條件沿用既有 service（`teacher-next-step`、各 own-scoped action）。
- 不改權限，除了新增管理員唯讀系列查詢（需 security review）。
- 系列管理頁現有的整批操作與確認視窗內容不變。
- 學員端「找課程」與「我的報名」已是一個系列一張，不改。

## 4. Schema 與文件影響

- Schema：僅 `Notification.recurringClassSeriesId`（additive、可為空）＋索引。HEAVY 票，用獨立 worktree 與獨立測試資料庫；同票更新 `docs/domain/data-model.md`。
- 不需更新 `state-machines.md`、`permissions.md`（管理員唯讀查詢沿用既有「管理員可讀全部課程」規則；若 review 判定需要，另行補述）。
- `docs/visual-acceptance-checklist.md` 補上系列卡、操作列、名單一排的檢查項。

## 5. 施工順序

先完成 `inline-member-enroll`（學員端就地報名，票 06–10），再做本批。學員單堂頁的期班標籤併入該批票 08。本批票券見 `docs/superpowers/plans/teacher-series-rollup/`。
