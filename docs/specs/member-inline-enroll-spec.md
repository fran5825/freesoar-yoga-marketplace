# 學員端就地報名：spec

建立日期：2026-10-10。來源：`/grill-with-docs`（2026-10-10，Q1–Q9 產品主人全部採用建議）。

**狀態：已施工（2026-10-11，`inline-member-enroll` 票 06–10）。** 取代 `member-inline-actions-and-card-cleanup-spec.md` 3.4、I7 的「沒報名的人看到的報名卡不變」。原本放在 `docs/superpowers/specs/` 的草稿已移到這裡。

## 1. 目標

延續「就地操作」邏輯：已報名的人已經不用跳頁就能請假、取消；現在**沒報名的人也不用跳頁就能報名**，並且報名表單只在需要時才佔版面。

## 2. 已決定的規則

| # | 決定 |
|---|------|
| Q1 | 三處列表的每一列都能直接報名：系列頁「挑一個上課日期」、單堂頁「同系列的其他場次」、期班頁「查看每一堂」中標示可單堂報名的列。三處共用同一個「列」元件。 |
| Q2 | 每一列按狀態顯示：沒報名＝**報名**（旁邊顯示剩幾個名額）；已報名的單堂＝**已報名**＋**取消報名**；整期學員的那一堂＝**已報名**＋**請假**（請假中＝**取消請假**）。單堂的「取消報名」不改叫請假（請假會保留名額，取消不會）。 |
| Q3 | 按「報名」後在該列下方展開：同意勾選（保留，必填）、「加備註」連結（預設收起）、確認按鈕。需老師確認的課程按鈕文字是「送出報名申請」。不做「全站同意一次」（會動資料模型與報名驗證，需另行決定）。 |
| Q4 | 單堂頁沒報名時：取消獨立的「報名這堂課程」卡；第一張課程資訊卡標題下方放「我要報名」（需確認的課程為「申請報名」），按下後表單在這張卡內展開。手機底部固定「前往報名」列保留，按下去直接展開。期班的單堂頁（選整期或只報這一堂）也併進第一張卡，邏輯相同。 |
| Q5 | 只收起學員報名相關的備註（單堂報名、重新報名、期班報名），統一用現有 `OptionalNotes`（「加備註」）。團主需求單、老師表單、管理員原因欄位不動。 |
| Q6 | 送出後頁面重新載入並捲到該列（沿用請假與取消請假的機制）。成功：該列變成新狀態，成功訊息在頁面最上方。失敗（例如剛好額滿）：該列表單維持展開並說明原因。 |
| Q7 | 額滿＝顯示「已額滿」無按鈕；已開始或不開放＝顯示原因無按鈕；沒登入＝仍有「報名」按鈕，按下後該列展開登入選項，登入完回到同一頁、該列自動展開，由本人勾選同意後才送出，不會自動報名。同系列列表中自己已報名或請假的場次也用這套列。 |
| Q8 | 施工等 `worktree-inline-actions` 合進 `main` 之後才開始，本批票排在它後面。 |
| Q9 | 本檔併入既有 spec；票券接在 `inline-member-actions` 票 06 起；無資料表、權限、state machine 變動，不需要新 ADR，不動 `data-model.md`、`state-machines.md`、`permissions.md`。 |

## 2.1 完整的列狀態（取代 Q2 的簡化版，Codex review 補充）

列狀態一律由 service layer（單堂與整期的操作資格沿用既有 `TermRowControl`、取消服務與 `re-enroll-eligibility`，不另外發明規則） 依「這位使用者在這一堂的報名紀錄＋這一堂目前能不能報」算出，元件只負責顯示，不自己判斷：

| 這位使用者的紀錄 | 列顯示 |
|---|---|
| 沒有紀錄、能報名 | 名額＋**報名**（需確認的課程為「申請報名」） |
| 沒有紀錄、額滿／不開放／已開始／老師非 approved | 原因文字，無按鈕 |
| `pending` 或 `confirmed`，**單堂報名**（沒有 `seriesEnrollmentId`），這一堂尚未開始 | 「等待確認」或「已報名」＋**取消報名**；已開始則只有狀態、無按鈕 |
| `pending` 或 `confirmed`，**屬於整期報名**（有 `seriesEnrollmentId`） | 狀態＋整期學員該列的動作，完全由既有 `TermRowControl` 決定：能請假＝**請假**；請假中且名額還在＝**取消請假**；請假中但不能取消請假（名額被報滿、已開始等）＝既有的原因文字；已開始＝無按鈕。這類列不會出現「取消報名」 |
| 自己取消、可重新報名（`reEnroll.state = available`） | **重新報名**（展開同樣的表單，送出帶 `reEnroll=1`） |
| 自己取消但額滿、已開始、老師非 approved | 原因文字，無按鈕 |
| 老師婉拒、管理員取消、已退出整期、整期被婉拒 | 原因文字，無按鈕（不顯示送出必然失敗的「報名」） |

期班頁「查看每一堂」的 `canEnrollSingle` 目前只代表「這一堂能單堂報名」，不含上表的重新報名與原因判斷；票 06 要把它擴成上表的列狀態，並讓期班頁與同系列列表讀到使用者自己的報名紀錄（單堂頁已有，系列頁與期班頁要補）。

## 2.2 返回、展開與 redirect 規則（Codex review 補充）

- 每一列有穩定 ID（`session-row-<classSessionId>`，沿用「就地操作」的 `session-row-` 前綴慣例但改用場次 ID，因為沒報名的列沒有 enrollmentId）。
- 就地操作的 action 一律把「來源頁路徑＋該列 ID」帶回，成功或失敗都 redirect 回**來源頁**（系列頁、單堂頁、期班頁），不是單堂頁；來源頁路徑要加進返回路徑白名單（現有 `safeTermRowReturnPath` 不接受系列頁，需擴充並維持「只接受站內路徑」的安全限制）。
- redirect 參數：`result`、`message`、`focus=<列 ID>`；失敗時另帶 `open=<列 ID>`，該列表單維持展開。
- 期班頁的「查看每一堂」預設收合；帶 `focus` 或 `open` 回來時要自動展開這個收合區再捲到該列。
- **失敗後的畫面以重新讀取的最新狀態為準**：`open=<列 ID>` 只在該列重新讀取後**仍然可報名**時才保持表單展開（例如備註或同意勾選的驗證錯誤）。若失敗原因讓這一列變成不可報名（例如剛好額滿），該列就改顯示 2.1 對應的原因文字（「已額滿」等），表單收起，並把失敗訊息顯示在該列上方（同一個 `focus` 列），讓使用者知道剛才為什麼沒成功。
- 登入流程：登入 action 帶同樣的來源頁與 `open=<列 ID>`，回來後該列自動展開，仍需本人勾選同意才送出。

## 2.3 價格與繳費規則（Codex review 補充，需產品主人確認）

老師可以單獨改某一場的 `priceNote`，報名服務也以該場價格建立紀錄；但系列頁只讀表頭場次的價格、期班頁讀系列價格、同系列列表只有日期。直接在列上報名前，學員必須看到**這一場實際適用的價格與繳費規則**：

- 列展開後，在同意勾選上方顯示這一場的 `priceNote` 與繳費與取消規則（沒填就不顯示該行）。
- 列表的 read service 要一併讀出每一場的 `priceNote` 與 `paymentRulesText`。
- 這是在原有「展開後有同意、備註、確認」之外**多一塊唯讀文字**，不改任何驗證與資料。

> 待產品主人確認：價格資訊放在展開區（本草稿的做法）。若某場價格與系列表頭不同，列上是否要多標一個「價格不同」小標籤，可之後再議，先不做。

## 3. 不變的規則

- 報名的資格、名額、老師 approved、同意勾選的驗證全部沿用既有 service layer（`enrollAction` 與 `validation.ts`），本批只改介面。
- 「只收整期」的期班，未報名者仍轉到期班頁；期班頁整期報名區維持現狀。
- 單堂取消與整期請假的後果不變（見既有 spec 與 `state-machines.md`）。

## 4. 建議票券（接在 `inline-member-actions` 之後）

| # | 票 | Mode | 說明 |
|---|----|------|------|
| 06 | 共用「報名列」元件與列狀態 | STANDARD | 依 2.1 的完整列狀態表由 service layer 計算（含自己的報名紀錄、重新報名、不可重報原因）；2.2 的返回與 redirect 規則（來源頁白名單、穩定列 ID、`focus`／`open`）；2.3 每一場價格與繳費規則；元件含就地展開、同意、「加備註」、登入回來自動展開。 |
| 07 | 系列頁（持續開課）每列可報名 | STANDARD | 圖 1：每列顯示名額與報名按鈕；自己已報名的列顯示取消報名；訪客可展開登入。 |
| 08 | 單堂頁：第一張卡內報名，同系列列表就地報名 | STANDARD | 取消 `ClassEnrollmentPanel` 與 `TermClassEnrollPanel` 兩張獨立卡；第一張卡放「我要報名」與展開表單；手機底部列；同系列其他場次用票 06 元件。 |
| 09 | 期班頁「查看每一堂」可單堂報名、重新報名收起備註 | STANDARD | 可單堂報名的列用票 06 元件；重新報名表單的備註改用「加備註」。 |

每張票測試至少涵蓋：可報名、需老師確認、額滿、已開始、`pending`、單堂已報名、整期請假與取消請假、自己取消可重新報名、老師婉拒與管理員取消不顯示報名按鈕、訪客登入回來、失敗時表單維持展開、期班收合區自動展開、各來源頁送出後回到來源頁、價格不同的場次顯示該場價格、手機無橫向溢出。

## 5. 風險與待確認

- 本批會改動 `ClassSummary`、`TermRowControls`、單堂頁，與進行中的 `inline-member-actions` 重疊，所以必須等它合併（Q8）。
- 沒有圖六的原圖，假設它是「我的報名」裡每一列的請假按鈕（上一批已完成）。
- 無需產品主人額外決定的 schema、權限或 state machine 變動。
