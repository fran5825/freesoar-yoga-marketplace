| D1 | 選定老師之後，團主和老師怎麼對時間（F1） | **A. 選定後互相看到聯絡方式**：團主看到被選定老師的聯絡方式，被選定的老師看到團體聯絡窗口。改的是「誰能看到哪些欄位」（權限），不動 schema、不動狀態機。代價：雙方在站外（電話、LINE）談，平台不知道談了什麼。<br>**B. 選定後改走合作邀請**：團主填好課程安排送給老師，老師確認後才成立課程，跟「已有合作老師」那條一樣。代價：要把需求接上合作邀請，動狀態機與資料關聯，屬 HEAVY，工作量大很多；而且老師確認前雙方還是需要先談時間，聯絡問題沒有消失。 | **A**。改動小、馬上解決卡關；直接開團那條已經讓受邀老師看到團體聯絡窗口，有前例（`ProposalSummary.tsx`）。 |

## Problem Statement

團主走「我需要找老師」這條路時，在兩個地方會卡住：

1. **選完老師，不知道怎麼跟老師對時間（F1）。** 建課表單要團主填「和老師確認後的實際時間」，但團主看不到老師的任何聯絡方式，站內也沒有可以討論的地方。被選定的老師也看不到團體的聯絡方式，自己的回應頁只寫「後續合作細節將另行安排」，沒人安排。結果團主只能猜一個時間，猜錯會撞到老師行程而建課失敗，或建出老師不知道的時間。
2. **建完課只是草稿，卻沒有任何地方提醒要開放報名（F2）。** 成功訊息和給團主、老師的通知都說「已經建立完成」；總覽「待你處理」只列需求和直接開團的邀請，不列課程；課程列表只有一個「草稿」標籤。團主建完就離開的話，學員永遠報不了名，老師也以為課已經開了。

## Solution

1. 團主選定老師後，需求詳情頁的那位老師旁邊直接顯示老師的聯絡方式；被選定的老師在自己的回應頁看到團體聯絡窗口。選定通知寫清楚「下一步是跟對方確認時間」，並直接連到看得到聯絡方式的那一頁。建課表單把老師回應的「可配合時段」放在時間欄旁邊。
2. 團主媒合建課後，課程還沒開放報名時：總覽「待你處理」出現這堂課、課程列表與課程頁寫明「學員還看不到」、給團主與老師的「課程已建立」通知改成講清楚還沒開放。其他兩條建課路線（直接開團、老師自建課）的通知文字不變。

## User Stories

聯絡方式（F1）：

1. 身為團主，選定老師後，我想在同一頁看到這位老師的聯絡方式，才能跟老師確認上課時間。
2. 身為團主，如果老師沒有留聯絡方式，我想知道老師看得到我團體的聯絡窗口、會主動聯絡我，而不是以為網站壞掉。
3. 身為團主，我在選定之前不想看到任何老師的聯絡方式，也不希望沒被選上的老師看到我的聯絡資料。
4. 身為被選定的老師，我想在通知裡知道下一步是跟團主確認時間，點下去就看到團體的聯絡窗口。
5. 身為被選定的老師，如果我還沒填聯絡方式，我想被提醒去填，讓團主也聯絡得到我。
6. 身為團主，填課程時間時，我想看到這位老師回應時寫的可配合時段，不用來回切頁。
7. 身為沒被選上的老師，我不會看到這個團體的聯絡窗口。
8. 身為團主，需求被取消後，原本選定的老師就不再看得到我的聯絡窗口。

開放報名提醒（F2）：

9. 身為團主，建完課後我想在總覽「待你處理」看到「這堂課還沒開放報名」，點了直接到那堂課。
10. 身為團主，在「我的課程」列表，我想一眼看出哪堂課學員還看不到。
11. 身為團主，在還沒開放的課程頁，我想看到一句話告訴我學員還看不到、按「開放報名」之後才能分享連結。
12. 身為團主，建完課收到的通知要寫「還沒開放報名」，而不是「已經建立完成」。
13. 身為授課老師，團主媒合建課後收到的通知，要讓我知道團主開放報名後學員才能報名。
14. 身為直接開團或自己開課的人，我收到的「課程已建立」通知維持原本的文字。
15. 身為團主，開課時間已經過了、無法再開放的草稿課，不要一直出現在「待你處理」。

## Implementation Decisions

### 聯絡方式（D1＝A、D2＝A；權限變更，需安全檢查）

- **團主看老師**：`src/domain/demand-response/organizer-read-service.ts` 的團主回應查詢，只有 `status = selected` 的那一筆多讀 `teacherProfile.contactInfo`。做法是查詢後在 domain 層把非 selected 回應的 `contactInfo` 去掉，或分兩次查詢；不要在畫面層才藏，避免 DTO 帶出去。所有權仍由既有查詢的 owner 條件保證（只查自己的需求）。
- **畫面**：`ResponseList.tsx` 在 selected 那張卡顯示「老師的聯絡方式」。`contactInfo` 為空、團體聯絡資料完整時，顯示「老師還沒留下聯絡方式。老師看得到你團體的聯絡窗口，會主動跟你聯絡確認時間。」
- **雙方都沒有聯絡方式**：送審時會檢查團體聯絡資料完整（`organization_contact_incomplete`），但之後 `updateOwnOrganization` 允許清空聯絡欄位，不會因為有進行中的需求而擋下。本 spec 不改這個驗證（改了會影響團主編輯團體，屬另一個決定），改成在畫面上偵測：判斷用現有的 `isOrganizationContactComplete`。
  - 團主需求詳情：老師 `contactInfo` 為空、且這筆需求所屬團體聯絡資料不完整時，selected 卡改顯示「你和老師目前都沒有可用的聯絡方式。請先補齊團體聯絡資料，老師才聯絡得到你。」連到 `/organizer/organizations/<團體 id>?returnTo=/organizer/demands/<需求 id>`（沿用既有 returnTo 白名單）。
  - 老師回應頁：團體聯絡資料有缺時，缺的欄位寫「團主尚未填寫」；三項都缺時加一句「團主目前沒有留下聯絡方式，請先到老師資料填寫你的聯絡方式，讓團主聯絡你。」
  - 這不保證一定聯絡得上（雙方都可以不填），但每一種組合畫面都會說實話並指出誰該補。
- **老師看團體**：`src/app/teacher/demands/[demandRequestId]/page.tsx` 的「自己的回應」分支，`ownResponse.status === "selected"` 時多讀並顯示團體名稱與聯絡窗口（`contactName`、`contactEmail`、`contactPhone`，跟 `ProposalSummary.tsx` 的「團體聯絡窗口」一樣）。查詢放在 domain 層，條件寫在 WHERE：需求存在、這位老師在這筆需求有 `selected` 的回應。不顯示團主個人帳號的 email。
- **何時不再顯示**：需求被取消時，既有流程會把回應改成 `declined`（`cancel-demand-request-core.ts`），條件自然不成立，不另外處理。課程取消不影響回應狀態，選定的老師仍看得到團體聯絡窗口（需要時才能聯絡退課事宜）。
- **文案**：`selected` 狀態的「恭喜，團主已選擇你的回應！後續合作細節將另行安排。」改成「團主選擇了你的回應。請用下方的團體聯絡窗口跟團主確認上課時間；團主建立課程後，你會收到通知。」老師的 `contactInfo` 為空時，加一句「你還沒有填聯絡方式，團主目前聯絡不到你」，連到 `/teacher/profile/payment`。
- **選定通知**：`demand_response_selected` 給老師（counterpart）的文案改成「你的回應已被選中：需求「X」。請跟團主確認上課時間，團體聯絡窗口在回應頁。」連結從「團體需求」列表改成這筆需求的老師回應頁 `/teacher/demands/<id>`：`link.ts` 的 `teacher_demand_request` 依通知類型決定，只有 `demand_response_selected` 連單筆；`demand_request_cancelled` 仍連列表（行為不變）。給團主（self）的文案改成「你已選定老師。請先跟老師確認上課時間，再到這筆需求建立課程。」，連結不變（已直達需求）。
- **老師總覽待辦**：`src/domain/class-session/teacher-next-step.ts` 的「等待團主建立課程」（已連到 `/teacher/demands/<id>`）文案改成「團主已選你合作「X」。請跟團主確認上課時間，團體聯絡窗口在回應頁；團主建立課程後會出現在「我的課程」。」`kind` 維持 `waiting`。
- **建課表單**：`src/app/organizer/demands/[demandRequestId]/page.tsx` 的建課區塊，在開始／結束時間上方顯示被選定老師的「可配合時段」（`proposedTimeSlots`，已讀出），以及「請先跟老師確認時間再填」。說明句「可以依和老師討論的結果調整」保留。
- **不做**：站內訊息、雙方聯絡紀錄、要求老師必填 `contactInfo`。

### 開放報名提醒（D3＝A；只改畫面與通知文案）

- **總覽「待你處理」**：`src/app/organizer/dashboard/page.tsx` 新增「還沒開放報名的課程」項目，條件：自己的課（`organizerProfileId` 是自己）、`status = draft`、`startAt` 晚於現在。開課時間已過的草稿無法開放（`openOwnClassSessionForEnrollment` 要求 `startAt > now`），也無法取消，所以不列入。資料用現有 `listOwnClassSessionsForOrganizer` 再篩選，或新增一個只查草稿的 domain 函式；不改 schema。待辦組成邏輯放 domain 層（比照 `organizer-class-proposal/todo.ts`），畫面只負責顯示。項目文字：「「課名」還沒開放報名」＋「學員還看不到這堂課」，連到 `/organizer/classes/<id>`。
- **入口完整性**：團主端讓草稿變成開放報名，只有課程頁的「開放報名」按鈕（`openForEnrollmentAction`）。老師端開放限 `teacher_initiated`（`open-class-session-core-for-teacher.ts`），系列全部開放（`open-all-draft-occurrences-core.ts`）只服務老師系列，直接開團在老師確認後一次建立並開放，不會留下草稿。所以提醒只需要跟著這一顆按鈕：開放成功後課程不再是 draft，待辦自然消失。
- **課程列表**：`src/app/organizer/classes/page.tsx` 草稿卡片多一行說明，依下方「草稿分兩種」：可開放寫「還沒開放報名，學員看不到」，已過期寫「開課時間已過，沒有開放報名」。
- **草稿分兩種**：「可開放的草稿」＝`status = draft` 且 `startAt` 晚於現在；「已過開課時間的草稿」＝`status = draft` 且 `startAt` 已過。後者開放（`openOwnClassSessionForEnrollment` 要求 `startAt > now`）和取消都會失敗，團主也沒有改課功能。判斷函式放 domain 層（例如 `class-session` 底下一個純函式），總覽、課程列表、課程頁、需求下一步共用，不各自比時間。
- **課程頁**：`src/app/organizer/classes/[classSessionId]/page.tsx`
  - 可開放的草稿：標題下方加一句「學員還看不到這堂課。確認時間、地點後按「開放報名」，就能複製連結分享給團員。」
  - 已過開課時間的草稿：**不再顯示「開放報名」按鈕**（目前 `available` 只看 `status === "draft"`，會顯示一顆按了一定失敗的按鈕），改顯示「開課時間已過，這堂課沒有開放報名，無法再開放。」並附兩個連結：「建立新的需求」（`/organizer/demands/new`）、「直接邀請合作老師開課」（`/organizer/class-proposals/new`）。不能指向原需求：原需求已是 `converted_to_class`，一筆需求只能建一堂課（建課會回 `class_session_already_exists`），回去也無法重新建課；本 spec 不新增重新建課的狀態轉換。這只是把按鈕條件改成跟 service 一致，不改狀態機。
  - 建課成功的提示從「課程已建立。」改成「課程已建立，還沒開放報名。」
- **需求下一步**：`src/domain/demand-request/next-step.ts` 的 `converted_to_class` 可選擇性收「課程是否為可開放的草稿／已過期草稿」；可開放時文案改成「課程已建立，還沒開放報名。到課程頁按「開放報名」後，就能分享連結。」，已過期時寫「課程已建立但沒有開放報名，開課時間已過。」`kind` 維持 `info`，避免需求與課程在「待你處理」各出現一次。需求列表、總覽、詳情都要傳同一個值，三處說法一致（沿用票 11 的規則）；沒傳時維持現有文案。- **通知文案**：`class_session_created` 的 copy builder 新增選填參數（例如 `notYetOpen: true`）。只有團主媒合建課（`create-class-session-core.ts`）傳這個參數：給團主「課程「X」已建立，還沒開放報名。到課程頁按「開放報名」後，就能分享連結給團員。」，給老師「團主建立了課程「X」。團主開放報名後，學員才能報名。」直接開團（`open-direct-class-core.ts`）與老師自建課（`create-teacher-class-session-core.ts`）不傳，文字不變。通知文字在發送當下存進 `Notification.title／body`，所以只影響之後的新通知，不動 schema、不回填舊通知。

## Testing Decisions

- 只測外部行為：看得到什麼、點了到哪裡、通知寫什麼。
- **權限（最重要）**：用 Playwright smoke（`tests/smoke/`，獨立埠）準備一筆需求、三位老師回應、選定其中一位：
  - 團主只在被選定那張卡看到聯絡方式；選定前任何卡都沒有。
  - 被選定的老師在回應頁看到團體聯絡窗口；沒被選上的兩位看不到。
  - 另一位團主打開這筆需求 → not-found（沿用既有規則）。
  - 需求取消後，原本選定的老師不再看到聯絡窗口。
  - 老師沒填 `contactInfo` 時，團主看到說明句、老師看到提醒與連結。
  - 需求送出後，團主把團體聯絡欄位清空：老師回應頁顯示「團主尚未填寫」；老師也沒填 `contactInfo` 時，團主看到「雙方都沒有聯絡方式」與補資料連結，補完後回到同一筆需求。
  - 老師總覽「等待團主建立課程」的文字有聯絡指引。
- **通知**：選定後老師通知的連結是 `/teacher/demands/<id>`；需求取消通知的連結仍是列表。媒合建課後團主與老師收到「還沒開放報名」的文字；直接開團與老師自建課的文字不變（可沿用 `notification-role-targets.spec.ts` 的 `notifyOverride` 攔截寫法）。
- **提醒**：媒合建課後總覽「待你處理」出現該課；按「開放報名」後消失；開課時間已過的草稿不出現在待辦；課程列表與課程頁的說明文字出現在草稿、不出現在已開放。
- **已過開課時間的草稿**：直接用資料庫建立一筆 `startAt` 已過的團主草稿課（測試 DB），課程頁沒有「開放報名」按鈕、顯示過期說明，兩個連結分別打開新需求表單與合作邀請表單；課程列表與需求下一步顯示過期文字。判斷可開放／過期的純函式用邊界時間（剛好等於現在）測一次。
