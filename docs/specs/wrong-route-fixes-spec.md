# 修正走錯路（A 組）：通知直達、申請頁導覽列、重複提示：spec

建立日期：2026-10-25。來源：`/feature-loop` 的 `grill-with-docs`（2026-10-25，Q1–Q6 產品主人回覆「全部照建議」）；問題來自 `docs/backlog.md` 第 25、26 項與 `docs/superpowers/plans/teacher-experience-walkthrough/2026-10-24-first-time-teacher-walkthrough.md` 的 F12。相關 ADR：無新增；沿用 [ADR 0008](../adr/0008-notification-series-grouping.md) 的通知系列合併，以及 `docs/domain/data-model.md` 既有的 `NotificationTargetType` 白名單做法。

## Problem Statement

同一個人在飛索常常同時有好幾種身分：自己帶課的老師，也幫社區揪團（團主），偶爾也報名別人的課（學員）；管理員也可能同時是團主或老師。

1. **通知連錯頁**：通知如果沒記下「是哪一筆資料」（target），系統就依收件人目前擁有的身分去猜要連到哪一頁，而且團主排第一。結果學員收到「課程取消」，點下去卻跑到團主的課程頁；管理員收到「有人送審需求」，卻連到自己的團主需求頁。email 裡的連結用同一套猜法，所以也會錯。
2. **申請頁導覽列寫「學員」**：剛登入、還沒送出老師申請的人打開老師申請頁，上方導覽列是學員專區，會以為自己登錯身分。
3. **同一個提示出現兩次**：單堂課開放報名後，「把報名連結傳給學員」寫了兩次；系列管理頁的收款提醒有兩塊靠得很近；團主按「送出審核」後，上下各出現一塊一樣的「確認送出需求」。

## Solution

1. 有可能送到多重身分帳號、又會被猜錯的通知，發送時一律帶 target，直接連到收件人那個身分該看的那一頁。新增 5 種 target（學員端的課程、團主／老師／管理員端的需求、管理員端的老師申請）。舊通知不回填，維持原本的猜法。
2. 已登入但還沒有老師資料的人，在老師申請頁用「老師專區」的精簡導覽列（總覽、老師資料、通知）。
3. 三個重複提示各留一個：單堂課的綠色訊息只寫「已開放報名。」；系列頁只留「全部開放報名」區塊裡的收款提醒；團主的確認區只出現在按下的那顆「送出審核」旁邊。

## User Stories

通知直達（以下「多重身分帳號」指同時是老師＋團主＋學員的帳號）：

1. 身為也是團主的學員，我收到「課程時間／地點異動」通知時，想點進去就看到那堂課的學員課程頁，才能確認新時間。
2. 身為也是老師的學員，我收到「課程取消」通知時，想連到「我的報名」，而不是我自己老師端的課程列表。
3. 身為也是團主的老師，我自己取消一堂單堂課後，想讓「課程取消」通知連到我老師端的那堂課。
4. 身為授課老師，團主取消了我們合作的課，我想讓通知連到我老師端的那堂課，而不是我自己團主身分的課程頁。
5. 身為團主，我取消一堂課或團主媒合建課成功後，想讓通知連到團主端的那堂課。
6. 身為也是團主的老師，團主媒合建課後收到「課程已建立」，想直達老師端的那堂課。
7. 身為也是老師的學員，我報名一堂需要審核的課後收到「報名待審核」，想連到那堂課的學員課程頁看自己的報名狀態。
8. 身為授課老師，有學員報名待審核時，想讓通知直達老師端的那堂課（整期報名則直達老師系列頁），才能馬上審核。
9. 身為學員，期班補課自動幫我報名後，想讓通知連到那堂補課的學員課程頁。
10. 身為也是老師的團主，我的需求被選定老師、被取消、或我剛送審、有老師回應時，想讓通知連到團主端的那筆需求。
11. 身為也是團主的老師，我回應的需求被選定或被取消時，想讓通知連到老師的「團體需求」頁，而不是團主需求頁。
12. 身為也是團主的管理員，有人送審需求或有老師回應時，想讓通知直達管理後台的那筆需求。
13. 身為也是老師的管理員，有人送出老師申請時，想讓通知直達管理後台的那位老師。
14. 身為任何收件人，我想讓 email 裡的連結跟站內通知連到同一頁。
15. 身為學員，系列裡同一天的多則通知合併成一則時，仍連到系列頁（ADR 0008 不變）。
16. 身為收件人，點進通知後如果沒有權限或那筆已失效，看到的是跟平常一樣的 not-found，不會看到別人的資料。
17. 身為產品主人，我想讓舊通知維持原本的連結，不因這次改動變成別的頁。

申請頁導覽列：

18. 身為剛登入、還沒送老師申請的人，我打開老師申請頁時想看到「老師專區」，才確定自己走對地方。
19. 身為還沒有老師資料的人，導覽列只放我現在能用的入口（總覽、老師資料、通知），不出現點了會打不開的頁面。

重複提示：

20. 身為老師，單堂課開放報名後，「把報名連結傳給學員」只想看到一次。
21. 身為老師，在系列管理頁開放草稿場次前，收款提醒只想看到一塊。
22. 身為團主，按「送出審核」後，確認區只想在我按的那顆按鈕旁邊出現一次。

## Implementation Decisions

### 通知 target（需產品主人確認：已於 2026-10-25 grill Q1 選「丙」放行，動 Prisma schema）

- `NotificationTargetType` 新增 5 個值（一個 migration，只用 `ALTER TYPE ... ADD VALUE`，不改既有資料）：

  | 新值 | targetId 是 | 連到 |
  |---|---|---|
  | `member_class_session` | 課程 id | 「課程異動」「報名待審核」「報名成立」→ 學員課程頁 `/classes/<id>`；「課程取消」→ 「我的報名」（取消後的課程頁學員打不開） |
  | `organizer_demand_request` | 需求 id | 團主需求詳情 `/organizer/demands/<id>` |
  | `teacher_demand_request` | 需求 id | 老師「團體需求」列表 `/teacher/demands`（老師端的需求詳情只看得到開放中的需求，被選定或取消後會打不開，所以連列表） |
  | `admin_demand_request` | 需求 id | 管理後台需求詳情 `/admin/demands/<id>` |
  | `admin_teacher_application` | 老師資料 id | 管理後台老師詳情 `/admin/teachers/<id>` |

- 連結推導仍只靠白名單 targetType（不存網址），但 `member_class_session` 依通知類型決定連課程頁還是「我的報名」，所以連結函式的對照表改成也能拿到通知類型。
- 要補 target 的發送點（其餘不變）：

  | 通知 | 收件人 → target |
  |---|---|
  | 課程已建立（團主媒合建課） | 老師 → `teacher_class_session`；團主 → `organizer_class_session` |
  | 課程異動（老師改單堂） | 學員 → `member_class_session` |
  | 課程取消（團主或管理員取消） | 團主 → `organizer_class_session`；老師 → `teacher_class_session`；學員 → `member_class_session` |
  | 課程取消（老師取消一堂） | 老師 → `teacher_class_session`；學員 → `member_class_session` |
  | 報名待審核（單堂） | 學員 → `member_class_session`；老師 → `teacher_class_session` |
  | 報名待審核（整期） | 老師 → `teacher_class_series`；學員不帶，照 ADR 0008 連期班頁（email 也要走系列連結，不能退回依身分猜） |
  | 補課自動報名（報名成立／待審核） | 學員 → `member_class_session` |
  | 需求送審 | 團主 → `organizer_demand_request`；管理員 → `admin_demand_request` |
  | 老師回應需求 | 團主 → `organizer_demand_request`；管理員 → `admin_demand_request` |
  | 選定老師 | 團主 → `organizer_demand_request`；老師 → `teacher_demand_request` |
  | 需求取消 | 團主 → `organizer_demand_request`；受影響老師 → `teacher_demand_request` |
  | 老師申請送出 | 管理員 → `admin_teacher_application`；申請人本人不變 |

- **不帶 target、維持現況的**：一次影響好幾堂的批次通知（建立、取消、改整個系列），照 ADR 0008 連系列頁；本來就只會給單一身分、不會猜錯的通知（例如課程完成、報名成立／取消給學員、需求公開／退回給團主、老師審核結果給老師）。
- 帶了單堂 target 的系列場次通知：單獨一則時直達那堂課；同系列同一天合併成一則時，照 ADR 0008 連系列頁。這是通知頁既有的規則，不改。
- 舊通知不回填（grill Q2）：當初沒記是哪一堂課或哪一筆需求，無法準確補；沒帶 target 時的猜法保留，給舊通知用。
- 點進去的頁面照原本的權限檢查，越權或已失效就是 not-found，不放寬任何權限。

### 申請頁導覽列（grill Q3）

- 已登入時，老師申請頁一律用「老師專區」外框；老師專區對沒有老師資料的人本來就只顯示總覽、老師資料、通知。未登入的訪客畫面不變；已通過或暫停的老師照舊直接轉到老師總覽。

### 重複提示（grill Q4–Q6）

- 單堂課開放報名的成功訊息改成「已開放報名。」，下一步交給頁面上的下一步提示。
- 系列管理頁拿掉場次清單上方那塊收款提醒，只留「還有 N 場草稿沒開放報名」區塊裡的那塊（兩塊出現的條件相同，後者本來就在場次清單上方）。
- 團主需求表單：記住按的是上方還是下方的「送出審核」，確認區只顯示在那一組按鈕旁；另一組位置照常顯示準備狀態與儲存結果。

### 文件

- 同一次改動更新 `docs/domain/data-model.md`（新 target 值）與通知連結的相關說明；backlog 第 25 項的三個重複提示、第 26 項完成後打勾。`docs/domain/state-machines.md` 不受影響（沒改任何狀態轉換）。

## Testing Decisions

- 好的測試只看外部行為：收件人在「我的通知」頁看到的連結網址，以及點進去看到的頁面；不檢查內部函式怎麼推導。
- 主要 seam：Playwright smoke（`tests/smoke/`）。用**一個同時是老師＋團主＋學員的帳號**當收件人，各觸發一次：學員端課程異動、課程取消、報名待審核；老師端被團主取消、自己取消單堂；團主端選定老師與需求取消；再用一個同時是團主的管理員收「需求送審」。斷言通知頁的連結指向對的身分頁面。
- email 連結：沿用既有 email 測試的寫法，檢查同一事件 email 內文的連結與站內一致（若既有測試沒有可用的寫法，至少涵蓋一種通知）。
- 申請頁導覽列：沒有老師資料的已登入帳號打開申請頁，看到「老師專區」與精簡導覽列。
- 重複提示：三個畫面各斷言提示只出現一次。
- 前例：`tests/smoke/notification.spec.ts`、`notifications-area.spec.ts`、`organizer-proposal-notifications.spec.ts`（target 直達）、`signed-in-navigation.spec.ts`（導覽列）。
- Playwright 用獨立埠 3100，`DATABASE_URL` 指向這輪 worktree 的獨立測試資料庫；schema 改動在 worktree 做。
- 驗證：`tsc`、lint、build、上述 smoke，以及會受影響的既有通知相關 smoke。

## Out of Scope

- 舊通知回填。
- backlog 第 25 項的請假合併內文、系列建課預設草稿與「未驗」各項。
- F15（登入後回到原頁）——留給登入流程檢視。
- 本來就不會猜錯的通知改帶 target（例如課程完成、報名成立給學員）。
- 老師端「需求詳情」在需求被選定或取消後的可見性——不改，通知改連列表。
- 新增通知類型、已讀狀態、通知設定。

## Further Notes

- 這次讓「依身分猜」只剩舊通知會用到。`docs/harness/review-checklist.md` 已有「通知要帶 target」一條，之後新增通知照那條走。
- 多重身分時 `notifyUsers` 依 userId 去重，保留第一個角色（例如團主自己當老師的課，只收團主那則）；這個行為不改，target 也跟著那個角色。
