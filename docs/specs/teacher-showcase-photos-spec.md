# 老師展示與課程封面照片 Spec

建立日期：2026-10-10。來源：產品主人 `/grill-with-docs`（飛索策略重整，Q1–Q23）。決策記錄見 [ADR 0007](../adr/0007-image-storage.md)；票券見 [票券總覽](../superpowers/plans/teacher-showcase-photos/ticket-breakdown.md)。

狀態：**Draft，待產品主人確認**。第 7 節的 schema 與權限變動是提案，核准前不得動 `prisma/schema.prisma`、`docs/domain/`。

## 1. 要解決的問題

目前課程頁、課程卡片與老師資料都只有文字，老師無法展現自己的風格，學員也無從從畫面了解老師的屬性與理念。老師唯一的圖片欄位是單張純網址的 `profilePhotoUrl`，課程沒有任何圖片欄位，也沒有公開的老師介紹頁。

## 2. 範圍

第一版做：

1. 圖片上傳基礎（R2、縮圖、格式與大小檢查）。
2. 老師頭像與最多 5 張個人照片，在老師資料頁管理。
3. 課程封面（單堂課、課程系列），可從已上傳照片挑，也可另外上傳。
4. 課程列表卡片與課程頁顯示封面與老師頭像。
5. 老師公開頁，由老師自己決定是否公開，預設不公開。
6. 管理員可下架任何照片，並通知老師。
7. 學員從課程頁可以前往老師公開頁。

第一版不做：教室獨立資料（見 backlog 第 21 項）、候補名單、AI 文案、金流、照片裁切編輯器、圖片留言或按讚、老師之間的照片共用。

## 3. 名詞

沿用 `docs/context/glossary.md`：**老師公開頁**、**教室**、**有填才顯示**、**課程封面**。

## 4. 決策（全部已確認）

| # | 決策 |
|---|------|
| S1 | 圖片由老師直接上傳檔案，存放在 Cloudflare R2（ADR 0007） |
| S2 | 老師最多 5 張個人照片，其中一張可指定為頭像；每堂課或每個課程系列最多 1 張封面 |
| S3 | 建課封面可挑自己已上傳的照片，也可在建課時另外上傳（另外上傳的照片同樣進入老師的照片庫） |
| S4 | 規格：JPG、PNG、WebP；單張 5 MB；上傳後自動縮成網頁尺寸；上傳時提醒「照片中若有其他學員的臉，請先取得對方同意」 |
| S5 | 管理員可下架任何照片；被下架的照片立即從所有頁面隱藏，並通知老師 |
| S6 | 老師公開頁由老師自己選擇是否公開，預設關閉；審核通過（`approved`）的老師才能開啟 |
| S7 | 有填才顯示：老師資料、文字與照片都選填，沒填就整塊不出現；唯一例外是課程列表卡片沒封面時顯示品牌色塊 |
| S8 | 課程卡片排版維持精簡（見第 5 節），不因為加照片而變得很長 |
| S9 | 老師修改照片不需重新審核，下架由管理員事後處理 |

## 5. 課程卡片排版

目標：加了封面之後，卡片比現在**只多一張圖的高度**，不多出任何資訊行；不論有沒有封面，每張卡片高度一致。

- 圖片區：固定比例（建議 3:2，手機可改 16:9 以節省高度），超出的部分置中裁切，不變形。沒有封面時顯示品牌色塊（米色底，帶瑜伽類型文字），不寫「尚未提供」。
- 圖片上方左上角：一個小標籤（來源或「持續開課」），其餘標籤移除。
- 圖片下方只留四件事：
  1. 課名（最多兩行，超出省略）。
  2. 一行時間（含每週固定的星期與時段）。
  3. 一行地點（超出省略）。
  4. 底部一列：左側老師小頭像加名字，右側剩餘名額提示（沒額度資訊就不顯示）。
- 現有「瑜伽類型：…」獨立一行、「老師名・擅長類型」、「下一個有名額…」長句，都不再單獨成行：瑜伽類型併入圖片上的標籤或色塊文字；擅長類型移到課程頁與老師頁；下一個有名額日期併入時間行的短提示。
- 用 `docs/visual-acceptance-checklist.md` 驗收；上線前在手機寬度（約 375 px）確認不會爆版，也不會因為老師照片明暗而影響文字可讀性（文字不壓在照片上）。

這是設計提案，實作票會先做版面預覽給產品主人確認，再套用到所有列表。

## 6. 規則

1. **誰能上傳**：審核通過（`approved`）的老師，只能管理自己的照片。申請中、待審、被退回的老師不能上傳，老師申請表（`/teachers/join`）**不再有照片欄位**（既有 `profilePhotoUrl` 舊資料保留在資料庫、不在新頁面顯示，老師通過後自行上傳）。管理員可下架任何照片；團主與學員不能上傳。
2. **老師頭像**：老師個人照片中指定一張作為頭像；未指定就沒有頭像。沿用既有 `profilePhotoUrl` 的資料需在實作票決定如何轉換（見第 7 節 M3）。
3. **課程封面的繼承**：課程系列設一張封面（`RecurringClassSeries.coverPhotoId`），系列內每一堂一律顯示系列封面；**不屬於任何系列的單堂課**才使用自己的 `ClassSession.coverPhotoId`。系列場次的 `coverPhotoId` 必須為空：寫入端（建課、編輯）拒絕對系列場次設定封面，資料庫以 check 約束保證（有 `recurringClassSeriesId` 時 `coverPhotoId` 為 NULL）。不支援系列內單堂另設不同封面。
4. **刪除正在被使用的照片**：老師刪除或管理員下架一張被當成課程封面的照片時，相關課程回到「沒有封面」（顯示色塊），不刪除課程。刪除前提示「這張照片目前用在 N 堂課」。
5. **隱私**：沒公開的老師公開頁，其個人照片庫不能被列出或搜尋。課程已公開時，課程封面與老師頭像、名字可以出現在課程頁與列表上（老師公開了這堂課）；其餘個人照片只出現在老師公開頁。檔案使用不可猜測的隨機 key。
6. **老師公開頁內容**（有填才顯示）：頭像與個人照片、顯示名稱、簡介、教學風格、證照與經歷、擅長類型、教學形式與服務地區、這位老師**公開列出**、目前開放報名的課程（只含單堂、持續開課、期班中設為「公開列在找課程」者；「僅透過連結招募」的課程不列出，沿用公開課程列表的可見性規則，不得因為出現在老師頁而被發現）。不顯示：email、電話、收款資訊、價格範圍以外的內部欄位、審核狀態。
7. **老師公開頁網址**：使用老師的不可猜測 ID（例如 `/teachers/[teacherProfileId]`），第一版不做自訂網址（slug）。
8. **未審核通過或被停權的老師**：公開頁一律不可見（回 404），照片也不出現在列表。

## 7. 資料與權限變動提案（需產品主人核准後才能動）

| # | 變動 | 影響 |
|---|------|------|
| M1 | 新增 `TeacherPhoto`（老師的照片）：`id`、`teacherProfileId`、`storageKey`、`width`、`height`、`status`（`active`／`removed_by_admin`）、`removedReason`、`removedAt`、`createdAt`、`sortOrder` | 新資料表；刪除老師時一併處理照片 |

| M3 | `TeacherProfile` 新增 `isPublicPageEnabled`（預設 false）與 `avatarPhotoId`；既有 `profilePhotoUrl` 在照片功能上線後停用（資料保留、不再顯示或寫入） | 老師資料頁會改、老師申請表單移除照片欄位；`profilePhotoUrl` 的現有使用處（`src/domain/teacher-profile`、`organizer-class-proposal`、`demand-response/organizer-read-service` 等）需逐一檢查 |
| M4 | 新增通知類型（管理員下架照片通知老師）：`NotificationType` 增加一項 | 要更新 `docs/product/notification-spec.md`；沿用站內通知，不新增 email |
| M5 | 權限：老師可上傳／刪除／排序自己的照片；管理員可下架任何照片；公開頁對訪客可見（僅限 `approved` 且 `isPublicPageEnabled`） | 要更新 `docs/domain/permissions.md`、`permissions-matrix.md`，並做 security review |
| M6 | 新路由：`/teachers/[teacherProfileId]`（公開頁）、老師資料頁的照片管理區、管理員下架入口 | 更新 `docs/product/route-map.md` |

## 7.1 封面要顯示的頁面與讀取路徑

封面與老師頭像必須在以下所有路徑一致顯示，實作票逐一列入、驗收逐一檢查，不能只改其中一條查詢：

| 頁面或列表 | 路由 | 備註 |
|---|---|---|
| 公開課程列表 | `/classes` | 單堂卡片與「持續開課」系列卡片 |
| 單堂課程頁 | `/classes/[classSessionId]` | 訪客與已登入會員使用不同的 read service，兩邊都要有封面與老師資訊 |
| 系列頁 | `/classes/series/[recurringClassSeriesId]` | 讀系列封面 |
| 期班頁 | `/classes/terms/[recurringClassSeriesId]` | 讀系列封面 |
| 老師端課程列表與詳情 | `/teacher/classes`、`/teacher/classes/series/[id]`、`/teacher/classes/[id]` | 老師可看見並更換封面 |
| 學員已報名課程 | `/member/enrollments` | 是否顯示小封面，於票 05 的版面預覽決定 |

## 8. 開放問題

1. **課程價格欄位**：付款狀態計畫（`2026-08-03-lightweight-payment-v0-plan.md` P5）的「應付金額」取自 `DemandResponse.proposedPrice`，但**老師開課（`teacher_initiated`）的課程沒有需求，也沒有價格欄位**（`ClassSession` 沒有 price）。付款票開工前要決定價格放哪裡。見票券總覽票 01。
2. 申請階段的老師不能上傳照片（6.1）：這會讓申請表少一個選填欄位，審核通過前老師頁沒有照片。若要讓申請者也能上傳，需放寬權限並處理審核前的圖片濫用，建議不放寬。
3. 老師公開頁是否要列出「已完成課程數」或評論：第一版不做，等試用後再看。
4. 照片裁切：第一版自動置中裁切；老師若反映常被切到臉，再評估加簡單的焦點選擇。

## 9. 驗收

- 老師可以上傳、排序、刪除個人照片，指定頭像，建課時選封面。
- 課程卡片在有封面、沒封面兩種情況下高度一致，手機寬度不爆版。
- 老師未公開時，訪客直接輸入公開頁網址看到 404；公開後可看到，關閉後立刻看不到。
- 管理員下架照片後，所有頁面立即不顯示，老師收到站內通知；使用該照片的課程回到色塊。
- 老師頁的課程區：公開課與「僅透過連結招募」的課程各一個情境，只有公開課出現。
- 只有照片、沒有簡介（或相反）的老師頁，沒填的區塊整塊不出現，不留空框。
- 沒有照片的老師與課程，所有既有功能（報名、通知、名單）完全正常。
