## 1. 目標與範圍

讓老師把「單堂、持續開課的常態班、有固定堂數的期班」都完整開出來並經營下去：一次開放報名、可以改課、可以中途結束，學員也能一次報名整期。

- 只涵蓋老師自己開的課（`teacher_initiated`）。團主媒合來的課不在本次範圍，維持既有規則（Q14）。
- 手機優先，沿用 `teacher-usability-redesign-spec.md` 已定的畫面骨架與品牌規則。
- 通知只做站內通知；email 等 backlog 第 10 項。

## 4. 規則

### 4.1 三種課程與系列型態

| 老師選的排程 | 系列型態 | 堂數 | 學員報名 |
| --- | --- | --- | --- |
| 單堂 | 不是系列 | 1 | 單堂報名 |
| 每週固定 → 持續開課 | 持續開課 | 首批 1–26，可一直生成更多 | 單堂報名 |
| 每週固定 → 期班，共 N 堂 | 期班 | N（1–26），不能生成更多 | 依期班報名方式 |
| 指定日期 | 期班 | 選定的日期（最多 26），不能生成更多 | 依期班報名方式 |

- 期班報名方式：「只收整期」或「整期和單堂都收」，建立時選。
- 系列型態與期班報名方式建立後不能改（本次未設計轉換流程）。
- 建立時的撞課規則不變：撞到的場次跳過並告知老師。期班若有場次被跳過，建立摘要須清楚顯示實際堂數。

### 4.2 開放報名（Q1、Q11）

- 建立系列時的「建立後全部開放報名」勾選框，預設不勾；勾選後，建立完成的場次直接進入 `open_for_enrollment`。
- 系列頁「全部開放報名」：把該系列所有尚未開始的 `draft` 場次改為 `open_for_enrollment`；已開始、已取消的場次不受影響。
- 「生成更多」的勾選框預設沿用老師上次在該系列的選擇（瀏覽器端記憶即可，不存成系列欄位）。
- 老師總覽：同一系列的草稿合併成一張卡片，顯示系列名稱、草稿場數與最近幾個日期，點進系列頁；單堂草稿卡片也要顯示日期。
- 推導規則：期班要能整期報名，期班內所有尚未開始、未取消的場次都必須已開放報名；尚有草稿時，期班頁顯示「尚未全部開放」，不提供整期報名。

### 4.3 公開設定（Q3、Q12、Q17）

- 系列建立時可選「公開列在找課程」或「僅透過連結招募」，預設僅透過連結招募（沿用現在系列的行為）。
- 單堂與系列建立後都可以改公開設定：
  - 持續開課：公開設定跟其他改課欄位一樣依套用範圍處理（Q10）——「只改這場」只改該場，「改這場和之後所有場次」改該場與之後未開始、未取消的場次並更新系列預設；更早的場次不變。
  - 期班：公開設定整期一致（推導規則 8），從任何一場修改都套用到所有未開始、未取消的場次與系列預設，不提供「只改這場」的公開例外，因為期班在找課程是一張卡片。
- 公開設定與開放報名仍是兩件事：公開只影響是否列在找課程，學員要能報名仍須課程已開放報名。
- 既有系列預設為不公開，行為不變。

### 4.4 持續開課與追加日期（Q4、Q16、Q20、Q22）

- 持續開課：尚未開始、未取消的未來場次少於 2 場時，老師總覽出現「生成更多」提醒，點進系列頁。0 場時也提醒（包括「從這場以後全部取消」之後，見 4.6）。
- 期班不能生成更多。
- 期班可以追加日期作為補課：
  - 追加後，尚未開始、未取消的場次合計不得超過 26 場。
  - 追加的場次沿用系列目前設定；若期班已全部開放報名，追加的場次也直接開放報名（推導規則，讓整期學員能自動報上）。
  - 已整期報名、尚未退出的學員自動報上補課場次，各自收到一則站內通知；不能來的人自行請假。
  - 補課場次的名額若容不下所有整期學員，不能追加，請老師先調高人數上限（推導規則，與 Q24 一致）。
  - 追加日期同樣跑撞課檢查，撞到就不建立該日期。

### 4.5 改課（Q5、Q7–Q10、Q12、Q14）

可改的條件：老師自己開的課、狀態為 `draft` 或 `open_for_enrollment`、尚未開始，且老師仍是已通過審核的狀態。

| 欄位 | 規則 | 通知已報名學員 |
| --- | --- | --- |
| 標題、說明、課程風格、瑜伽類型 | 隨時可改，驗證規則同建立 | 不通知 |
| 日期與時間 | 可改；必須仍在未來；重跑撞課檢查 | 通知（`class_session_changed`） |
| 地點 | 可改 | 通知 |
| 人數上限 | 可加大；調小不得低於目前 `pending` + `confirmed` 人數 | 不通知 |
| 公開設定 | 可改，見 4.3 | 不通知 |
| 是否需要確認報名 | 本次不開放修改（未訪談，避免影響待確認中的報名） | — |

- 系列場次改課時，老師選擇套用範圍：
  - 「只改這場」：只改這一場，系列設定不變。
  - 「改這場和之後所有場次」：套用到這場及之後所有尚未開始、未取消的場次，並更新系列設定，之後生成或追加的場次沿用。
  - 不能改星期幾。要改上課的星期，請用「從這場以後全部取消」後建立新系列。
  - 批次改時間時，任一場撞課就整批不改，並指出撞到哪一場（推導規則，避免一半改成功一半沒改）。
- 期班改單場時間、地點，通知該場已報名的學員（含整期學員）。
- 已完成、已取消、已開始的課不能改；團主媒合來的課不能由老師改。

### 4.6 停課（Q6、Q13）

- 取消單場、取消整個系列：沿用既有規則與連帶取消報名、通知。
- 「從這場以後全部取消」：取消這場與之後所有尚未開始、未取消的場次，連帶取消報名並通知；之前的場次照常。確認視窗列出實際會取消的場次與人數。
- 持續開課的系列取消後仍可生成更多；系列不新增「已結束」狀態。
- 期班「從這場以後全部取消」等於提前結束這一期；整期報名紀錄保留，已上過的場次紀錄不受影響。

### 4.7 期班報名（Q19、Q23–Q27）

- **整期報名**：報上這一期所有尚未開始、未取消的場次。
  - 最後一堂開始前都可以報；期班頁寫明「剩 N 堂」。
  - 剩下每一場都要有空位（`pending` + `confirmed` 小於人數上限）才能報整期；只要一場滿了，就不能報整期。
  - 同一位學員對同一期班只能有一筆整期報名。已退出整期的學員不能再報整期（推導規則 5，與現行「取消的單堂報名不能重報」一致；現行每位學員每場只能有一筆報名紀錄）。
  - 學員已用單堂報名過其中幾場（狀態為 `pending` 或 `confirmed`），再報整期時，那幾場的既有報名併入整期報名、保留原狀態，名額檢查只計算本次新增的場次（推導規則 9）；曾經取消過某場單堂報名的學員，該場不能被整期報名重新加入，因此不能報整期，畫面須說明原因。
- **單堂報名**：只有「整期和單堂都收」的期班提供，只占用該場名額。「只收整期」的期班不提供單堂報名。
- **需要老師確認的期班**：整期報名新增的每一場都先是 `pending` 並占用名額；老師對這位學員確認或婉拒一次，就套用到這筆整期報名底下所有尚未開始的場次。
  - 確認：底下 `pending` 的場次改為 `confirmed`。
  - 婉拒：整期報名改為婉拒，底下由整期報名新增的未開始場次取消；併入前就已存在的單堂報名脫離整期報名、恢復為原本的單堂報名並保留狀態（推導規則 9）。
  - 屬於整期報名的逐場報名，不能透過單場的確認／婉拒操作個別處理（server 端也拒絕），避免整期狀態不一致。
- **請假**：整期學員取消單一場，其他場保留，空出的名額可給單堂報名。
- **退出整期**：取消這筆整期報名底下所有尚未開始的場次；已上過或已完成的場次紀錄保留。
- **通知**：整期報名、老師確認或婉拒整期報名，各只發一則站內通知，不按場次重複發。補課自動報上、改時間地點、取消場次仍依該場通知。學員請假或退出整期，比照現行學員取消報名：只通知學員本人，不另外通知老師（老師在名單看得到）。

### 4.8 學員端呈現（Q15、Q27）

- 公開找課程：一個公開的期班只顯示一張卡片，例如「共 10 堂，剩 7 堂，每週二 19:00」。持續開課的公開場次維持逐場顯示。
  - 篩選（日期、星期、地點、類型）：期班只要有任何一場尚未開始的場次符合篩選就顯示，但卡片上的堂數一律是整期的完整數字，不是符合篩選的場數。
  - 是否顯示為可報名：只收整期的期班，以「現在能不能報整期」判斷（剩下每一場都已開放且有空位）；整期和單堂都收的期班，能報整期或任一場還有單堂空位就算可報名。預設排除額滿時，依這個判斷。
  - 星期篩選以每一場實際上課日期判斷，不用系列的星期設定（補課可能在別的星期）。
- 期班頁：顯示期間、全部日期、剩餘堂數、報名方式；提供「報名整期」，若也收單堂，下方列出每一場可單獨報名。
- 單堂課程頁：屬於系列時，列出同系列其他尚未開始的場次（只列學員本來就看得到的場次）。
- 學員「我的課程」：一筆整期報名合併成一張卡片，點開看到每一場的狀態，以及請假和退出整期的操作。

### 4.9 老師端呈現

- 系列頁標示系列型態（持續開課／期班）與期班報名方式。
- 期班頁或系列頁可看到整期學員名單、每位學員的請假場次，以及待確認的整期報名。
- 單場詳情的報名名單標示每位學員是整期或單堂報名。

| S18 | 常態班中途結束 | 「從這場以後全部取消」，之前照上；之後想恢復可再生成 |
| S19 | 先只用連結招生，之後改成公開 | 改公開設定後列在找課程 |
| S20 | 學員在課程頁看到同系列下週的課 | 列出並可點進去報名 |
| S21 | 學員在找課程看到期班 | 只有一張期班卡片 |
| S22 | 暫停中的老師 | 不能改課、開放報名、追加日期或生成更多（沿用既有資格規則） |
| S23 | 其他老師嘗試改不是自己的課或系列 | 一律拒絕 |

## 6. 資料與規則影響（實作票各自處理）

- **Schema（additive，HEAVY）**：
  - `RecurringClassSeries` 新增：是否公開、系列型態（持續開課／期班）、期班報名方式。
  - 新增整期報名紀錄資料表，`Enrollment` 新增可為空的欄位指向它，並持久保存子報名來源（由整期報名新增／既有單堂併入），供整期婉拒時區分處理。設計理由見 ADR 0005。
  - Migration 預設：既有每週固定系列 → 持續開課、不公開；既有指定日期系列 → 期班、整期和單堂都收、不公開。目前沒有正式上線資料；上線後要重新評估 migration 風險。
- **State machine**：`ClassSession` 新增「建立後可在 `draft`／`open_for_enrollment` 改課」，取代 `state-machines.md`「建立後不提供編輯」的規則；新增整期報名的狀態與它和逐場報名的連動。實作前須先更新 `state-machines.md`。
- **權限**：新增老師 own-scoped 的改課、批次開放報名、追加日期、從這場以後取消；新增學員對整期報名的報名、請假、退出；都要經過安全檢查，更新 `permissions.md`。
- **併發與鎖定協定**（2026-10-04 Codex review 補）：
  - 現況：單場報名先鎖 `ClassSession` 再鎖 `TeacherProfile`；撞課檢查要求先鎖 `TeacherProfile`。兩者若在改課中直接組合，會形成循環等待。
  - 全站統一順序：`RecurringClassSeries` → `ClassSession`（多場時依 id 排序）→ `TeacherProfile`。改課需要撞課檢查時，先鎖要改的場次，再鎖老師，撞課 helper 須支援「場次已鎖」的呼叫方式，不得反向取鎖。
  - 所有改動「系列場次集合或整期報名」的操作，都先鎖該系列列作為序列化邊界：整期報名、退出整期、整期確認／婉拒、追加補課、生成更多、全部開放報名、批次改課、從這場以後全部取消。鎖到系列後，在同一 transaction 內重新讀取場次集合、有效整期學員與 26 場上限。
  - 單場報名維持既有路徑（場次 → 老師），不鎖系列；名額由場次鎖保護。因此多場操作必須在取得場次鎖之後，才確認名額、狀態與既有報名。
  - 「生成更多」與追加補課：鎖系列、重讀設定與最後一場、計算日期、建立場次，全部在同一個 transaction 內完成（現行實作在 transaction 外計算、逐場各開 transaction，須改造，見票 01）。
  - 每張相關票須有交錯執行的測試（例如整期報名與追加補課、退出與追加、兩次追加、改課與單場報名）。
- **通知**：沿用既有 `class_session_changed`；整期報名相關通知是否需要新的通知類型，在實作規劃時決定，若需新增 enum 值則屬 schema 變更。

## 7. 不做

- 整期付款、退款、折扣（V1 無線上付款）。
- 背景自動排程、自動生成場次、自動開放報名。
- 改星期幾、改系列型態、改期班報名方式、改「是否需要確認報名」。
- 老師改團主媒合來的課；團主多堂課（backlog 第 18 項）。
- Email 通知（backlog 第 10 項）。
- 一次勾選多場的單堂報名。

## 8. 推導規則（核准票券時一併確認）

以下規則不是訪談中逐題詢問的，而是為了讓 Q1–Q28 能一致運作而推導的；核准對應票券時請一併確認：

1. 期班尚有草稿場次時，不提供整期報名（4.2）。
2. 期班已全部開放時，追加的補課場次直接開放報名（4.4）。
3. 補課場次名額容不下所有整期學員時，不能追加（4.4）。
4. 批次改時間任一場撞課就整批不改（4.5）。
5. 退出整期後不能再報整期（4.7；2026-10-04 改，原寫「可重報」與現行「取消後不能重報」的報名規則矛盾）。
6. 「是否需要確認報名」本次不開放修改（4.5）。
7. 系列型態與期班報名方式建立後不能改（4.1）。
8. 期班的公開設定整期一致，不提供單場公開例外（4.3）。
9. 已單堂報名的場次併入整期報名並保留狀態，名額只算新增場次；整期被婉拒時，併入的單堂報名脫離整期、恢復為單堂（4.7）。
10. 學員請假、退出整期不另外通知老師（4.7）。
11. 暫停中的老師不能開放報名：現行單場「開放報名」沒有檢查老師狀態，票 04 一併補上 server 端檢查（S22）。
