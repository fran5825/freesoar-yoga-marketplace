# 學員流程與排版順手度整理計畫（2026-09-25，規劃中，等使用者確認票單後才動工）

這份記錄 2026-09-25 跟 Franz 用 grill 方式討論出的決策。目標：學員從點進課程連結、看詳細資訊、註冊登入到報名完成，步驟更少、排版跟全站（含團主、老師端）一致、一眼找得到資訊與下一步。

參考 `docs/organizer-usability-plan.md`、`docs/teacher-usability-plan.md` 的做法（待處理提示、列表整張可點、詳情頁下一步放最上面、共用 `RoleShell`）。用詞見 `docs/context/glossary.md`。

**範圍限制**：不動資料庫結構、不動狀態機、不動權限；不做付款、不做 LINE／Facebook 登入；不動團主、老師與管理員頁面；不動 V1 scope。

## 現況問題

- `/member/dashboard`、`/member/enrollments` 沒有 `layout.tsx`，沒有導覽列，離開頁面只能按瀏覽器上一頁（backlog 第 5 項）。
- 頁寬不一致：學員頁 `max-w-3xl`、課程詳情 `max-w-2xl`、公開 header `max-w-6xl`；團主、老師端已統一 `max-w-4xl`。
- 報名狀態標籤的文字對照表在 `member/dashboard`、`member/enrollments`、`classes/[id]` 各複製一份。
- `/classes` 課程卡片沒有名額與開放狀態；篩選是兩個下拉選單加送出按鈕，沒有空狀態說明。
- 課程詳情頁：報名待老師確認時只有一行文字；不能直接取消，只有連結到「我的報名」。
- 「我的報名」卡片不能點進課程詳情；沒有「待你處理」；空狀態文案還寫「團主分享的連結」，但老師開課現在也是公開的。
- 未登入訪客從首頁到完成報名約 5 次點擊。

## 定案決策

| # | 決策 |
| --- | --- |
| 1 | 最高優先路徑：點分享連結 → 看課程詳情 → 報名；其次是瀏覽找課。發起需求（學員自己發起）不在這次範圍。 |
| 2 | 驗收指標：連結到完成報名 ≤ 3 個畫面；手機單手可完成；課程詳情頁一屏內看到時間、地點、老師、費用（不在此列，見決策 8）、剩餘名額、報名鈕。 |
| 3 | 先瀏覽、按「報名」才要求登入；登入後回到原課程頁（沿用現有 `callbackUrl`）。回到原頁後仍需學員自己按一次「報名」，不自動送出（取消後不能重報，誤報名代價較高）。 |
| 4 | 註冊只用 Google 帳號的姓名與 email，不加額外必填資料。 |
| 5 | 介面用詞統一：學員（不用會員）；課程來源標籤為「團主團課」「老師開課」。identifier 維持 `member`、`origin`。 |
| 6 | 團主團課與老師開課放同一個課程列表，卡片與詳情用來源標籤區分。 |
| 7 | 新增 `member/layout.tsx`，套用 `RoleShell`，頁寬統一 `max-w-4xl`；選單「找課程／我的報名／通知」。學員頁（含 `/classes` 系列於登入後）的標題層級、卡片樣式對齊團主端。 |
| 8 | 課程列表與詳情補「剩餘名額」與狀態標籤（開放報名／額滿／已開始）。`ClassSession` 沒有價格欄位，這次不顯示費用，也不動 schema；價格另記 backlog。 |
| 9 | 報名狀態標籤抽成共用元件，取代 3 個頁面各自複製的對照表。 |
| 10 | 課程列表篩選改成 tag-chip 即時篩選，加「只看還有名額」；無結果時顯示空狀態說明與下一步。 |
| 11 | 報名完成後留在詳情頁：頂部成功橫幅、按鈕變狀態標籤、附「查看我的報名」連結；不新增獨立成功頁。 |
| 12 | 報名需老師確認（`requiresApproval`）時，明確顯示「已送出，老師確認後會通知你」，並在「我的報名」置頂。 |
| 13 | 詳情頁也能取消報名（沿用現有確認流程與 service 規則）；確認框明寫「取消後無法再次報名此課程」。取消規則本身不改。 |
| 14 | 「我的報名」頂部加「待你處理」（待老師確認、已完成課程待評價）；卡片整張可點進課程詳情；空狀態改成「去找一堂課」按鈕連到 `/classes`。 |
| 15 | 保留 `/member/dashboard`，改成「待你處理＋即將上課」的首頁，與團主、老師總覽一致。 |

## 需要注意的前置查證（動工前先做）

- 決策 8：確認 `capacity` 與 confirmed／pending 報名數要怎麼算「剩餘名額」（pending 是否佔名額），以現有 `enrollment-service` 的規則為準，不自訂新規則。
- 決策 13：確認詳情頁能重用現有 `cancelEnrollment` server action 與其權限檢查；若需要新增 action，要走 service layer 並做本人權限檢查（涉及權限，動工前做 security review）。
- 決策 14：「已完成待評價」要能用現有資料判斷（confirmed 報名＋completed 課程＋尚無 review）；查不到就先不放這一項並回報。
- 決策 7：`/classes` 是公開頁，未登入訪客的 header 不能被 `member/layout` 影響；確認 `/classes` 系列維持公開 header，登入後版面統一的做法。

## 實作建議分批（每批做完由 Franz 看過畫面再下一批）

1. 學員外框、頁寬統一、共用報名狀態標籤（決策 7、9）
2. 課程詳情頁：名額與狀態、報名成功橫幅、待確認下一步、詳情頁取消（決策 8、11、12、13）
3. 課程列表：tag-chip 篩選、名額與來源標籤、空狀態（決策 6、8、10）
4. 「我的報名」與 dashboard：待你處理、卡片可點、空狀態文案（決策 14、15）

## 不做的事

- 付款與價格顯示、LINE／Facebook 登入、額外註冊欄位、獨立報名成功頁、登入後自動報名、學員自己發起需求的流程調整。
