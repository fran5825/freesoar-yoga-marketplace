## 前次實作前的問題（歷史基線）

以下是 2026-09-25 規劃時的問題，不代表目前仍未實作。2026-10-03 第二輪已對照程式確認共用外框、導覽、待處理區、詳情頁與狀態篩選存在；本輪紀錄見文件末尾。

- 5 個頁面頁寬有 3 種：總覽 `max-w-4xl`、列表頁 `max-w-6xl`、課程詳情 `max-w-2xl`。
- 導覽列是每頁各自貼的小字英文連結（`AdminNav`），沒有標示目前頁面，也不是共用 layout。
- 總覽只有數字卡，看不出哪一筆要處理。
- 只有課程有詳情頁；老師審核（595 行）與需求審核（378 行）把所有操作塞在列表裡。
- 沒有連結通往 `/admin/*`；`/account` 沒有管理員卡片（backlog 第 103 行）。
- 同一帳號同時是老師／團主／管理員時，各後台之間無法直接切換，要先回 `/account`。
- 標題與欄位是英文（Dashboard、Contact name…），跟團主／老師端不一致。
- 組織頁純查看，沒有審核操作。

### 程式查證（read-only，非畫面驗收）

- 既有共用 `RoleShell`／統一頁寬、中文導覽與目前頁標示、待審列表連到詳情、狀態篩選、退回範本及危險操作確認都已存在。
- 老師、需求、課程詳情的返回連結不保留原篩選；老師暫停／恢復後也回到預設待審列表，可能讓剛操作的老師離開眼前。
- 團體卡片只有需求／課程數字，無法點擊追到相關資料。
- 老師與需求詳情的完整審核／退回表單在資料內容前；退回表單預設展開。Q7 已核准改為先讀摘要與內容再操作，尚未實作。
- 老師審核使用 `AdminSubmitButton`，需求審核仍使用一般按鈕，送出中回饋不一致。
- 總覽 KPI 是純數字，不能直接前往對應資料。
- 需求列表沒有獨立的「已媒合」「已建課」「已取消」分類，這些資料目前只能在「全部」查找。
- admin 取消單筆報名的 service 已支援未開始課程的 `confirmed`／`pending` 報名，但詳情 UI 只在 `confirmed` 顯示取消入口；Q13 已核准補齊 `pending` 入口，尚未實作。
- 課程／報名取消沒有原因參數或持久化欄位；不能沿用前次「原因維持必填」文字而新增資料欄位。已取消報名仍受既有唯一性與不可重報規則限制。
- 現有取消單筆報名完成後留在課程詳情；Q12 已核准名單內操作為 Q8 的例外，完成後保留名單搜尋／篩選。
- 課程模型已有課程風格（多選）、瑜伽類型、來源、是否需老師確認報名等欄位，老師詳情已有呈現；admin DTO 與詳情仍只讀取或顯示其中一部分。補齊讀取與顯示不需要 schema 變更，具體範圍待下一輪確認。
- 需求被退回後須另建新需求，不能重新送審原需求；admin 退回範本與詳情 fallback 目前卻有「重新送審」文案。須修正文案而非改變現行終局規則；老師申請則可修改後重新送審，兩者不能混用。
- 「即將開始課程」KPI 限開放報名且尚未開始，單純連到開放中分頁會包含已過期資料；「已確認報名」沒有全站逐筆列表。KPI 連結須精準承接原計數條件，不能用近似目的頁製造不一致。
- `/account` 已移除，由角色切換承接入口；課程列表預設為「全部」，因為課程沒有 admin 待審流程。前次相關文字保留為歷史紀錄，不作為新增能力的依據。
- 尚未執行 desktop／mobile 畫面驗收或測試；上述缺口依程式閱讀判斷。
