### 22. 開通 Cloudflare R2（你要做的，老師照片功能正式上線前，2026-10-10）

程式已經能把照片存到 R2（ADR 0007），**沒設定時照片功能會直接關閉、其他功能不受影響**（開發與測試用本機資料夾）。你要做的事：

1. 註冊 [Cloudflare](https://dash.cloudflare.com/)，開通 R2（據我所知需要先綁一張信用卡，免費額度每月 10 GB 儲存、流量不收費，實際以畫面為準）。
2. 在 R2 建立一個 bucket（名稱例如 `freesoar-photos`），並開啟公開存取（用 R2 提供的公開網域，或綁定自己的網域），記下**公開網址開頭**。
3. 建立 API token（R2 的「Object Read & Write」權限，限定這個 bucket），取得 Access Key ID 與 Secret Access Key。**不要貼在對話裡。**
4. 打開專案的 `.env`，自己填：`STORAGE_DRIVER="r2"`、`R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_BUCKET`、`R2_PUBLIC_BASE_URL`（欄位說明見 `.env.example`）。
5. 跟 Claude 說「R2 設定好了，幫我測一次上傳」，用一張真的照片確認能上傳、能顯示、能刪除。
6. 正式上線時，把同樣的設定放到主機的環境變數；上線主機另案決定（見 `docs/engineering/hosting-comparison.md`）。

- 目前只有 Google（`src/auth.ts` 的 `providers`）。
- 順序：等第 1 項品牌色做完後再做。
- 前置（你才能做）：

  - 去 Meta 開發者後台建立 App，取得金鑰；Meta 需要隱私權政策網址（相依第 3 項）。
- 注意：LINE 不一定會提供 email，但資料庫的 `User.email` 目前是唯一欄位，實作時要處理沒有 email 的情況。
- 登入頁（`src/app/sign-in/page.tsx`）已經是品牌風格，新增按鈕只需要放在同一張卡片內。
- 2026-10-05 補充（學員流程票 05 討論）：
  - 票 05 會把登入按鈕做成共用的「登入選項」元件（課程頁與 `/sign-in` 共用），依「目前開放的登入方式」清單畫按鈕；新增登入方式時加進清單即可，兩頁同時更新。
  - 回程 cookie、callback 安全檢查、取消或失敗後的友善頁面，都跟用哪種方式登入無關，之後加 LINE、Facebook 時可以直接沿用。
  - 各種登入方式之後要注意的事：
    - **LINE、Facebook**：Auth.js 都有現成的設定，大部分是加設定和申請金鑰（見上方前置）。LINE 不一定提供 email，但資料庫規定每個帳號的 email 不能重複，要處理沒有 email 的帳號。
    - **Email 登入**：Auth.js 會寄一封含登入連結的信，要先接好寄信服務（技術清單上的 Resend）。學員要離開網站去收信，回程網址要寫在信裡的連結上，不只靠 cookie。
    - **手機登入**：已決定不做「手機加密碼」（見「已決定不做」）。若改做「簡訊驗證碼」，Auth.js 沒有內建，要接第三方簡訊服務，每封簡訊都要付費，真的要做時要另外評估費用。
    - **同一個人用不同方式登入**：例如先用 Google、後來改用 LINE，系統預設會當成兩個不同的帳號，報名紀錄也會分開。要不要合併成一個帳號，是加第二種登入方式時一定要先決定的產品決策。

## 小提醒（踩過的坑）

- **跑 Playwright 測試請用獨立埠**：`PORT=3100 npx playwright test ...`（會自動啟動編譯後的正式版伺服器，需先 `npm run build`）。直接跑會連到你開著的開發伺服器（3000 埠），開發模式下按鈕常點了沒反應，造成假失敗（2026-09-25 查出，`organizer-demand.spec`、需求送出的通知測試都是這樣被誤判成舊測試問題）。

- **測試**：`teacher-join` 那組測試在「開發模式」（`npm run dev`）下會因為網頁還沒載入完就被點擊而失敗，用正式建置跑（`npm run test:smoke`，它會先 build）就會通過。
- **開發伺服器**：改了 `globals.css` 之後如果畫面變成沒有顏色，通常是舊的開發伺服器沒有重新編譯；停掉重開，並在瀏覽器按 Ctrl+Shift+R 強制重新整理。
