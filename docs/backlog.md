### 2. 檢查 Google Cloud Console 的「品牌」頁面

- 目的：Google 登入畫面上會顯示的應用程式名稱、logo、隱私權政策與服務條款連結，都在這裡設定。

### 5. 登入後頁面缺少 header，需要設計「登入後專用」的簡化版

- 現象（2026-09-20 盤點）：全站 35 個頁面裡，有共用 header（logo＋導覽列＋登入狀態）的只有 6 個公開頁；`/classes`、`/classes/[課程ID]` 這 2 個公開瀏覽頁已在 2026-09-20 補上。
- 還沒補的 24 個，都是「登入後才看得到」的角色後台頁面：團主（7）、老師（8）、學員（2）、管理員（5）、帳戶／通知（2）。這些頁面目前完全沒有導覽列，使用者進去之後只能靠瀏覽器上一頁離開。
- 已決定的方向：不要直接沿用公開頁那個 header——它的導覽列是「發起團課、搜尋課程、老師合作、關於飛索」這種行銷用連結，對「已經登入、正在後台工作」的團主／老師來說用途不大。要另外設計一個**登入後專用的簡化 header**：只放 logo＋登入狀態＋回首頁，不放行銷導覽列；之後可能還要依角色加上對應捷徑（例如團主可能想要「我的需求」「我的課程」這種直接連結）。
- 下一步：這是一個需要先做詳細規劃（spec／plan）的功能，不是直接動手改樣式而已——牽涉到「登入後的角色導覽該長怎樣」這種產品設計問題。等你有空時說「來規劃 backlog 第 5 項」，會先討論規劃再動工，不會跳過規劃直接寫程式。

- **測試**：`teacher-join` 那組測試在「開發模式」（`npm run dev`）下會因為網頁還沒載入完就被點擊而失敗，用正式建置跑（`npm run test:smoke`，它會先 build）就會通過。
